# 품질 보수 작업 계약·체크리스트

상태: 구현·비교 평가 완료, 전체 의미 품질은 미통과. 규모 XL. 사용자 ‘추천하는 순서로 보수작업 진행’ 승인에 따라 [후보 6개](2026-09-29_quality-improvement-proposal.md)를 구현·검증했다. architecture/main에 문서, backend·frontend/dev에 구현만 둔다. 기존 미커밋 변경을 보존하며 배포·커밋·푸시는 이번 범위에 없다. 결과·채택 범위·미해결 사항은 [최종 보고서](2026-09-29_quality-repair-report.md)를 따른다.

## 순서와 계약

1. 검증·전달(후보1+3): 두 번째 호출에서 기존 판단과 독립 새 후보를 모두 받는다. 파일별 점검 대표 줄은 서버가 연결한다. 첫 응답이 스키마/위치 검증에 실패하면 남은 한 호출로 원문 코드만 독립 재검토한다. 잘못된 초안은 재전송하지 않는다. 두 번째 실패를 정상 0건으로 반환하지 않는다.
2. 의미·수정안(후보2): 실행하지 않는 제한 연산 검사와 정상 입력 보존 정보를 추가한다. 지원 밖은 미검증. 자연어 수정안을 검증 완료로 표시하지 않는다. 결함과 수정안 상태를 분리한다.
3. 부족한 문맥(후보4): 첫 검토가 요청한 제공 파일의 심볼만 같은 SHA에서 제한 취득한다. 정확히 요청한 범위/누락 사유를 표시하며 필수 변경 코드를 밀어내지 않는다. 임의 URL/저장소/경로는 받지 않는다.
4. 보안 근거(후보5): 제한된 정적 입력→위험 연산 근거를 독립 결과로 보존한다. 정확한 의존성 버전의 공개 취약점 조회는 별도 어댑터와 모의 전송 검증을 먼저 수행한다. 제품에서 동의하지 않은 새로운 외부 정보원으로 프로젝트 메타데이터를 보내지 않는다.
5. 추론·구조화 API(후보6+3): 같은 모델/입력에서 구조화 Responses와 조건부 추론을 평가한다. 효과·호환성 미확인 후보는 기본값으로 활성화하지 않는다. 제품 기본 Flash·2회·팀30회/일을 유지한다.

## 위험과 검증

적용: Terminal Ops, Verification Loop, 출력/권한/외부 전송 경계 검사. 기존 REVIEW/STANDARDS 소유 계약, ADR-REVIEW-013을 갱신한다. 소스 eval/exec/import/build 금지, 비밀 필터와 고정 SHA/권한/취소/lease/예약 유지. 분석 코드는 Linux 격리 테스트에서만 검사하고 대상 코드를 실행하지 않는다.

먼저 순수 계약·회귀 테스트, 이후 작업자/DB·프론트 테스트와 빌드를 실행한다. 평가 자료는 기존42개 공개·합성 재현과 새 독립 경계 사례이며 원본 비공개 저장소를 추가 반출하지 않는다. 이번 유료 검증 상한은 **600회**(현재 캠페인 잔여3,090회 안). 기준/단독/조합과 출력 예산을 기록한다. 동일 입력·동일 모델에서 탐지·전달·설명·수정안·정상 오탐을 분리한다. 호출 전에 기존 원장에 예약하고 실패도 집계한다. 단순 명칭 변경 자료를 독립 사례로 세지 않는다. 새 사례도 관찰 뒤 수정에 쓰면 회귀셋으로 전환한다.

채택 기준: 고정 중요 결함에 새 누락0, 정상 오탐·위험 수정안·전달 실패 증가0. 통과하지 않는 선택 기능은 비활성 상태로 남기고 한계를 보고한다. 전체 코드 안전이나 누락0을 보증하지 않는다. 롤백은 새 정책/프롬프트만 되돌리며 과거 결과·원장·기록은 수정하지 않는다.
