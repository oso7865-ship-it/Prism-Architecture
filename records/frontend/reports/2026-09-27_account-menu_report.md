## 설계와 변경

계획은 [account-menu](../docs/work-plans/2026-09-27_account-menu.md). 사용자가 제공한 헤더 캡처에서 아바타·이름·화살표의 불안정한 배치를 확인했다. 기존 summary는 flex center였으나 화살표가 문자 ⌄라서 글꼴의 기준선에 영향을 받았다. 부모 상자 중심 정렬만으로는 화살표 자체가 가운데 보이지 않았다.

| 위치 | 이전 | 변경 |
|---|---|---|
| 소유 컴포넌트 | HomeView의 한 줄 내장 마크업 | auth/AccountMenu.vue로 계정 표시·펼침 패널·Escape 소유 |
| 트리거 | 경계 없는54px 영역 |46px 높이의 단일 클릭 영역·얇은 테두리 |
| 정렬 | 크기 다른 span3개 |32px 아바타 / 축소 가능한 이름 /16px SVG의 grid |
| 화살표 | 문자 ⌄ |공통 AppIcon의 chevron-down, 열리면 방향 전환 |
| 긴 이름 | 모바일 nth-child 규칙 |명시적 account-name 말줄임·전체 접근 이름/title/펼친 이름 보존 |
| 패널 | 고정 top52px |트리거 아래8px·오른쪽 맞춤·viewport 폭 제한 |
| 로그아웃 | 부모 API 함수 직접 연결 |logout 이벤트로 기존 부모 함수 호출, 처리 중 중복 클릭 차단 유지 |

글자 크기를 계속 줄이거나 x축 넘침을 숨기지 않았다. 파란색 토큰·기존 전역 CSS 관례와 네이티브 details를 재사용했다. hover/open 색 변화와 SVG 방향으로 상태를 알린다. 애니메이션을 추가하지 않았다. 로그아웃 API·라우트·세션 처리 로직은 유지했다.

## 검증·제한

- 기존 테스트108개 PASS, 타입 검사·Vite 빌드 PASS. 단순 위치 변경을 흉내 내는 테스트를 새로 추가하지 않았다.
- UI pattern audit: AccountMenu/HomeView/AppIcon3파일, 후보0. 자동 검사만으로 UI 품질을 판정하지 않았다. 최초 --help 호출은 경로로 해석되어0파일 검사였고 이후 실제3파일을 명시했다.
- 실제 CUA 브라우저: Enter/Space로 열기, 로그아웃 버튼에서 Escape로 닫기, 트리거로 포커스 복귀 확인. 실제 로그아웃 API는 호출하지 않았다.
- 320px에서 아이콘·이름·SVG의 중심 y=31.5px로 동일, 트리거46px, 패널 x15~285·간격8px, 문서305px로 넘침 없음. 나머지 너비의 관측치는 responsive-results.json에 기록한다.
- 320px 저장 캡처 육안 확인. 긴 이름은 CSS 축소·말줄임과 전체 이름 보존을 코드로 확인했으며 실제 계정명을 바꿔 테스트하지 않았다. 모든 브라우저/스크린리더/확대율 검증을 의미하지 않는다.
- P0: 기존 사용자 데이터·logout emit 연결 유지. P1: 단일 클릭 대상 명확화. P2: 접근 이름·장식 aria-hidden·focus-visible·키보드 닫기 확인. P3: 공통 토큰/SVG 재사용. P4: 실제 너비 측정. P5: 계정 조작을 한 영역으로 묶기 위한 테두리. P6: 새 모션 없음.
- 기존 AI 하루30회·모델 일반 표기 유지. 새 유료호출0, 추가50회 승인 사용량 변화 없음.
- 범위: 계정 메뉴 정렬 수정. 전체 서비스의 모든 레이아웃을 재설계한 것으로 표현하지 않는다.

증거는 저장소 밖 ../../audit-artifacts/2026-09-27-account-menu/에 보관한다. 소스·문서만 커밋 후보이며 공개 저장소에 개인 화면을 자동 게시하지 않는다. dev working tree이며 커밋·push·배포 미수행.
