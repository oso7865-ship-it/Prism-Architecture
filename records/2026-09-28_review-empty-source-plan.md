# 빈 리뷰 재검토와 사이트 내 코드 보기 작업 계약

- 요청: 완료 리뷰의 제안·질문 0건 원인 수정, GitHub로 나가지 않고 코드 확인.
- 범위: backend/dev 리뷰 worker·하네스·소스 API, frontend/dev 리뷰 카드·범위·코드 뷰어. 설계/기록은 architecture/main에만 둔다. 기존 AWS 문서 변경 보존. 자동 커밋/배포 제외.
- 증거: 9/28 최근 4개 결과는 call_attempts=1, verification=NO_CANDIDATES, issues/questions=0. 화면 누락이나 verifier DROP이 아니라 빈 초안 즉시 완료 경로다. 과거 지적이 존재했다는 사실만으로 실제 결함 누락을 증명하지 않는다.
- 결정: 빈 초안은 동일 입력으로 독립적인 2차 검토를 진행하고 변경 파일마다 대표 근거 줄·짧은 관측 결과를 요구한다. 모든 변경 파일의 체크와 새 제안은 서버 위치/형식/비밀정보 검증을 통과해야 완료한다. 2차 답변 장애는 실패 처리. 정상 0건은 허용한다. 기존 결과는 수정하지 않는다.
- 제한: 최대 2회, 재시도 없음, 접수 하루 30회, 호출 전 권한·연결·취소·lease 예약 유지. 새로 발견한 항목을 별도 verifier 검증 완료라고 표시하지 않는다. 전체 코드/런타임 안전 보장 아님.
- 코드 API: 서버 결과의 file_id만 허용, 고정 HEAD, 연결 세대와 팀 권한을 취득 전후 검사. 한 응답 80줄·줄당 300자, 원본 취득 200KB/20초, no-store, DB/로그/브라우저 저장소 미보관. 대표 줄·근거 줄 이동과 이전/다음 구간 지원. legacy issue key 경로 유지.
- UI: 카드와 검토 파일에서 코드 열기, 줄 강조·키보드·로딩/오류/재시도/닫기, 과거 미재검토 결과 구분. 0건도 검토 파일·제한·재검토 근거 접근 가능.
- 적용: UI/UX Design, Vue UI Polish, Verification Loop; Security Gate. 위험: 권한 경계, 유료 2차 호출, false positive. 기존 보호 장치와 회귀 테스트로 확인.
- 검증: strict 체크/부분 파일/허위 위치/정상 0건·발견 항목, 취소·철회·lease·사용량·재생 방지 Linux DB 테스트. 소스 허용목록/권한/고정 SHA/페이지/비밀/철회 테스트. frontend 빌드·회귀·실제 브라우저. 필요 시 합성 코드만 유료 평가(기존 한도 내 집계), 조직 코드 신규 전송 없음.
- 진행: 설계·구현·검증 완료. 결과와 제한은 동명 report 참조.
