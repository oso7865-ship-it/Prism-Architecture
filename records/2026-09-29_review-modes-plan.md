# 리뷰·취약점·팀 규칙 구현 계획

상태: 구현·로컬 검증 완료. 사용자 승인: “그렇게 전부 진행해줘”.
읽은 기준: CORE, REVIEW, PRIVACY, PACKAGE-RULES, CONVENTIONS, ADR-REVIEW-008/010/011. 작업 크기 XL. 아키텍처 main, 제품 dev. 보고서·설계는 이 저장소에만 보관한다.

## 제품 계약

- PR의 코드 점검은 기존 결정적 검사다. AI 탭은 코드 리뷰 / 취약점 / 팀 규칙으로 나눈다. 각각 독립 실행·이력이며 하루 30회와 동시 1개 제한은 팀 전체 합산이다. 자동으로 세 번 청구하지 않는다.
- 취약점은 기존 보안 규칙 탐지와 전용 AI 검토를 구분한다. AI는 입력→위험 연산·권한 경계의 코드 근거를 제시해야 한다. 전체 저장소 보안 보증·동적 공격·의존성 CVE 스캔을 주장하지 않는다.
- 팀 규칙은 저장소별 Markdown/텍스트 문서를 등록한다. 최초 범위는 UTF-8 .md/.txt, 최대64KiB·문서8개/저장소·문서당20버전이다. 업로드와 텍스트 편집을 제공한다. 문서 종류는 컨벤션/패키지 구조. 소유자만 등록·수정·비활성화·삭제, 멤버는 열람한다.
- 문서 원문과 섹션은 팀 비공개 DB에 저장한다. 버전 불변, 활성 버전 변경 가능, 동시 수정은 이전 버전 번호로 방어한다. 코드 원문 비저장 정책과 구별해 화면에 알린다. 삭제 시 원문·섹션을 삭제하고 진행 중 전송을 차단한다. 과거 리뷰는 문서 식별자/버전/제목/섹션 출처와 판정만 남긴다.
- 섹션 단위 인덱스는 저장 시 생성. 경로 적용 범위·예외를 먼저 적용하고 BM25 기반 어휘 검색으로 관련 규칙을 검색한다. 임베딩 모델은 추가하지 않는다. 한국어/영문 토큰과 코드 식별자를 사용하며 의미 벡터 검색이라고 표시하지 않는다.
- 명시적 필수 규칙은 검색 순위로 제거하지 않는다. 모든 적용 필수 섹션이 입력 예산을 넘으면 실행 전 안내 오류, 조용한 누락 금지. 결정적 규칙은 이름 접미사/금지 import/경로 배치의 제한된 구조화 설정이며 문서와 별개 확인 입력이다. 임의 정규식·명령은 실행하지 않는다.
- 팀 규칙 AI 항목은 실제 전달된 섹션 ID와 코드 근거를 함께 요구한다. 없는 출처/다른 팀 문서/적용 제외 경로의 인용은 거부한다. 문서 내용은 비신뢰 데이터로만 전달하고 시스템 지시를 바꿀 수 없다.
- 고정 HEAD 코드 16KiB/파일·48KiB 전체 제한 유지. 규칙 문맥은 별도 최대12KiB. 최대2회 LLM 호출·회당60초 유지. 모델 답변의 형식·출처 확인은 의미적 정답 보증이 아니다.

## 위험과 복구

사용자가 기능 구현을 승인했으며 기존 인증을 재사용한다. 외부 코드 실행·권한 확대·비용 한도 확대는 없다. 마이그레이션은 새 테이블과 기본 CODE 목적/빈 문서 스냅샷만 추가한다. 기존 리뷰 결과는 변경하지 않는다. 다운그레이드는 새 데이터가 있으면 거부하여 실수로 문서·리뷰 구분을 지우지 않는다. 실제 DB 변경 전 백업하고 테스트는 BSOD 이력이 있는 Windows 네이티브 DB 대신 Linux Docker에서 수행한다.
