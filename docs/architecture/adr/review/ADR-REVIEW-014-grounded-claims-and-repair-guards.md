# ADR-REVIEW-014: 제한 계산에 근거한 설명과 수정안 반례 차단

> ID: `ADR-REVIEW-014` · 소유: `REVIEW` · 기준: `2026-09-29`

- 상태: `ACCEPTED`
- 근거: 배포 전 권고 중 ‘남은 전달 실패와 잘못된 원인·수정안 설명 보수’ 1번만 진행하라는 사용자 위임.
- 대체하는 ADR: [ADR-REVIEW-013](ADR-REVIEW-013-recovery-and-evidence-checks.md). 아래 출력·설명 계약을 보강하며 기존 복구·권한·문맥·호출 한도는 유지한다.
- 대체한 ADR: 없음.

## 배경

코드에 이미 있는 조건을 미확인 전제로 적어 응답 전체가 거부되는 문제, 제공된 기본값과 다른 분기를 설명하는 문제, 정상 입력의 반환값까지 바꾸는 수정안을 확인했다. C3는 위치·형식 점수를 통과했지만 실제 설명 검수에서는 실패했다. 모델이 계산 자료를 받는 것과 정확히 설명하는 것은 별개다.

## 결정

SUPPORTED의 assumptions는 비어 있고 NEEDS_CONTEXT는 미확인 전제와 INFO/WARNING만 허용한다는 기존 계약을 JSON Schema의 조건 관계로도 제공한다. 서버가 전제를 삭제하거나 확정 판단으로 승격하지 않는다. 선택적 contract_quote는 제공한 코드·문서·평가 계약에 실제 존재하는 짧은 인용만 허용하고 결과 저장 전에 제거한다. 인용 일치가 요구사항 해석의 정확성을 보장하지 않는다.

제한 식 비교에서 발견한 성공값 변경 반례를 두 번째 검토에 제공한다. 초안과 진단의 합은 기존24,000byte 안에 들어야 하며 소스를 줄여 진단을 넣지 않는다. 최종 수정안에도 같은 반례가 남으면 suggestion을 안전한 확인 안내로 바꾸고 suggestion_check.withheld=true로 기록한다. 원래 결함·근거·반례는 보존한다. 반례를 찾지 못한 자연어 제안은 여전히 미검증이다.

제공된 작은 순수 Python 함수와 리터럴 단언을 제한 상수 전파로 계산한다. 기본값·선택 분기·반환값만 다루며 임의 호출·프로젝트 실행·import·eval/exec는 하지 않는다. 연속 코드16KiB, AST500노드, 계산160단계·호출깊이4·인자4개·파일별관측6개·관측파일4개를 상한으로 한다. 단일 Java int 곱셈→long 반환도 완전한 작은 클래스 형태가 맞을 때만 유한 관측을 제공한다. 지원 밖 구문은 제외하며 검사하지 않은 코드를 안전하다고 판정하지 않는다.

CODE 결과에서 제공된 Python 단언의 기대값과 계산값이 다르고 실제 계산 경로에 변경 줄이 있으면 서버가 해당 차이를 설명한다. 항목은 같은 제공 줄 검증을 거치고 origin=STATIC_PROJECTION으로 구별한다. 테스트 실행·전체 프로그램 증명·테스트 기대값 자체의 정당성을 주장하지 않는다. 구체적 패치를 검증하지 못한 경우 그 사실을 명시한다. 해당 파일·대표 줄이 정확히 같은 모델 설명만 교체하고 다른 위치는 유지한다. 최대4개 후보·전체10개 결과 한도 안에서 추가하며 결과 공간 부족은 grounding.omitted로 알린다. 모델 응답 자체의 검증 실패를 이 기능이 성공으로 바꾸지는 않는다.

prompt_version에 이 조합을 반영한다. Flash·추론OFF·출력2,000토큰·최대2회·팀하루30회·동시1개·기존16/48KiB 코드 예산·권한/취소/예약·원문 비저장·150초를 유지한다. DDL 변경과 과거 결과 재작성은 없다.

## 대안

프롬프트만 강화(C1), 제한 계산 정보를 모델에 제공(C2/C3), 좁은 단언 차이의 설명을 서버가 소유(C4)를 비교했다. C1/C2는 누락·오탐, C3는 실제 원인·수정안 오류가 남았다. 전체 코드 실행이나 임의 패치 검증은 권한·비용·안전 경계를 크게 바꾸므로 채택하지 않는다.

## 영향과 한계

작은 지원 구간에서 설명의 재해석 오류를 줄이는 대신 구체적 수정 코드 제안이 덜 상세해질 수 있다. 같은 위치의 다른 모델 지적도 교체될 수 있어 이 예외를 일반 의미 중복 제거로 확대하지 않는다. 단언이 없는 실제 서비스 코드, import·가드·동적 호출·다른 언어 전반에는 적용되지 않는다. 성공값 변경도 의도된 계약 변경일 수 있으므로 차단은 보수적인 안내이며 패치의 오답 증명은 아니다.

C4의54사례와 문제3쌍 반복을 합한66평가는 형식66/66·위치 기준 누락0·정상 오탐1이다. CA3건은 서버 설명으로 대체한 제품 결과이므로 모델 자체의 의미 정확도로 집계하지 않는다. 정상 복사본 사례에서 요구사항을 추측한 오탐이 남았으며 전체 품질 승인과 구별한다.
