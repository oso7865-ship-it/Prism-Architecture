# 사용자 표시 문구 전수 점검

## 작업 계약과 설계

- 요청: 화면에 내부 컬럼·상태·오류코드가 그대로 노출되는지 확인하고 사용자 친화적인 표현을 검증한다.
- 범위/규모: M. frontend dev의 로그인·홈·팀/초대·저장소/동기화·PR/활동·정적 분석·AI 리뷰/검토 범위/개인 기록. 기존 미커밋 변경을 보존한다.
- 현재 확인: StatusBadge의 알 수 없는 값 원문 fallback, 분석 error_code/reason 원문 fallback, PR 활동 state 직접 표시, 소유권 이전의 ADMIN, 새 V3 SYNTAX_PARTIAL/CONTEXT_UNAVAILABLE 미번역이 있다. 실제 화면과 코드 근거를 구분한다.
- 표시 계약: 서버 컬럼·enum은 API/저장/분기/링크에서 유지하고 사용자에게 보이는 텍스트만 번역한다. 파일 경로·PR 제목·사용자 코드·규칙 식별자·커밋은 의미 있는 원본으로 보존한다. 진단 버전은 설명이 있는 접힘 영역으로 둔다. 알 수 없는 값도 원문·빈칸·다른 확정 상태 대신 '확인 필요'와 다음 행동을 표시한다.
- 구현: 기존 컴포넌트와 색상·레이아웃 유지. 표시 사전은 해당 feature가 소유하며 공통 컴포넌트의 fallback도 안전하게 한다. 오류는 앱이 작성한 안내만 보여주고 서버/네트워크 예외 원문을 출력하지 않는다. GitHub 숫자 식별자는 사용자명/프로필 중심으로 안내하며 기존 초대에서 사용자명을 모르면 조작 대상 구분에 필요한 식별 정보를 설명한다.
- 검증: 모든 Vue 템플릿 바인딩 정적 검수 → 백엔드 발행 코드와 사전 대조 → 전체 알려진 코드/새 코드/악성·빈 값의 표시 단위 검사 → 실제 Vue 렌더 검사 → 기존 frontend 테스트·타입·빌드 → 실데이터 화면/모바일 캡처 및 오류·희귀 상태는 합성 fixture로 분리.
- 성공 기준: 앱 소유 필드의 raw enum/컬럼/UUID가 일반 표시 문구로 새지 않는다. 알 수 없는 상태도 사실을 추측하지 않는다. 다음 행동을 이해할 수 있고 원래 요청/권한/결과/탐색 의미는 유지한다.
- 적용: 제품 FRONTEND/CORE/PACKAGE-RULES, Product Design audit, 프로젝트 UI/UX·Vue polish·verification-loop·terminal-ops. 문구/표시 수정은 일반 위험이며 새로운 인증·권한·DB 계약/ADR 변경 없음.
- 제외: DB migration, 새로운 권한·실계정 역할 변경·초대 전송·저장소 해제, 유료 AI 호출, 전체 디자인 재설계, 배포/커밋/push. 기존 실제 결과를 고치지 않는다.
- 한계: 실제 계정의 현재 데이터에 없는 실패/역할 상태는 fixture 검증이다. 코드/AI 자유 서술 안의 프로그램 변수명은 제품 내부 필드와 구분하며 기계적으로 번역하지 않는다.
