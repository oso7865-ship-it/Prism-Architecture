상태: 실험 완료, 제품 자동 채택 없음. [결과 보고서](2026-09-29_quality-lab-report.md). 범위 XL. 사용자 요청: 서로 다른 접근 최소10가지, DeepSeek 요청 최소1,000회·이번 실험 최대5,000회. 이전 승인 원장1,563회는 보존하고 새 캠페인 사용량을 별도 집계한다. 호출 전 예약·실패 포함·자동 HTTP 재시도0. 새 승인 한도는 캠페인5,000회이며 누적 절대 상한6,563회다.

읽은 문서: CORE, REVIEW, PACKAGE-RULES, CONVENTIONS, 기존 recall-repair와 predeploy-quality 보고서, Verification Loop/Terminal Ops/Troubleshooting Report. 변경은 backend dev의 평가 코드·테스트·fixture와 architecture main의 기록에 한정한다. 이전 미커밋 제품 작업은 보존한다. 프론트/제품 설정/DB/조직 코드/배포/게시 변경은 이번 실험에 포함하지 않는다.

## 질문과 판정

정보 부족, 연산 오해, 무관한 문맥의 방해, 검증 단계 공통 오류를 구분한다. 결함 위치 적중·정상 오탐·불필요 질문·형식 실패·구체 입력의 예측값·토큰·시간을 별도로 기록한다. 합성 자료와 미리 작성한 정답만 사용하며 고객 코드·비밀키를 전송하지 않는다. 분석 대상 문자열이나 모델이 작성한 코드를 실행하지 않는다. 기준 동작은 별도 손작성 함수/상수로 검사한다.

공통 진단 출력은 제품의 ReviewOutput에 관측값(probes)을 추가한 평가 전용 스키마다. 공통 대조군도 이 스키마를 사용하므로 제품 성능 수치로 오인하지 않는다. 관측값은 구체 호출 결과이며 숨은 사고과정이 아니다. 별도 제품 경로 비교도 수행한다. 정답/결함 라벨/채점표는 모델 입력에서 제외한다. 자연어 원인·개선안까지 자동 판정한 것으로 표현하지 않는다.

## 실행 순서와 예산

1. 합성 개발20사례(정상/결함 쌍)와 별도16사례를 모델 호출 전에 해시 고정. Java/Python/JS/TS와 문서 규칙 포함. 독립 사람 라벨 검수는 미완료로 표시한다.
2. 개발20사례×2반복×전체14접근: 계획960호출. 실패 단계도 기록하며 같은 요청을 자동 재시도하지 않는다.
3. 개발 결과로 공통 대조군과 후보2개를 선정하고 사전 동결한16사례×2반복으로 별도 검증한다. 결과를 본 후 지침을 바꾸면 새 후보로 취급하고 기존 검증셋의 독립성을 주장하지 않는다.
4. 현재 제품 경로(초안→검증/빈 재검토)와 비교한다. 정상·결함과 관측값 정확도, 실패/토큰/지연을 보고한다.
5. 정상적으로 서비스가 응답한다면 최소1,000호출을 채운다. 인증/결제/연속 장애라면 무의미한 실패 요청을 반복하지 않고 중단 원인을 기록한다. 1차 목표 약1,100~1,300회, 상한5,000회. 숫자를 채우기 위한 무관한 요청은 하지 않는다.

평가 동시성은 최대4개로 제한하고 재시작 시 완료 항목을 재호출하지 않는다. 제품의 팀 하루30회/동시1개 정책은 변경하지 않는다. 모델·입력/지침/결과 해시·구조 검증 실패·최종 판정과 선택 사유를 architecture 기록에 남긴다.

## 실행 중 기록한 2차 설계 (별도 검증 응답을 보기 전)

개발 실험에서 AST/이전 코드가 있어도 range 간격을 잘못 해석하고, 정상 동작임을 설명하면서 issue를 등록하는 사례를 확인했다. 원래 실험의 입력/지침은 바꾸지 않는다. 후속 E14(공식 언어 규칙 근거 제공), E15(실제/요구 동작의 차이와 응답 내부 일관성을 확인하는 출력 판단) 두 후보를 사전 고정해 개발20+검증16사례×2회, 총144회 추가한다. E14는 Python에만 문서가 붙으므로 언어별 효과를 구분해야 한다. [range/불리언/복사](https://docs.python.org/3/library/stdtypes.html#ranges), [max](https://docs.python.org/3/library/functions.html#max), [기본 인자](https://docs.python.org/3/tutorial/controlflow.html#default-argument-values)의 일반 원리만 수동 요약하며 정답·사례별 해설은 보내지 않는다.

제품 경로 비교는 새36사례에서 현행+개발 결과로 고른 단일 초안 호출 후보를 비교하고, 기존 공개 PR 최소 재현6사례×2회도 현행 경로에 추가한다. 최대168호출이며 기존 공개 재현은 새 검증셋으로 부르지 않는다. 총계는 약1,400~1,500회 예상, 캠페인5,000회 상한 유지.

채점 정정: Java의 `java.lang.NullPointerException`과 `NullPointerException`은 같은 예외다. 이를 문자열 불일치로 오답 처리한 결과는 원래 strict 점수·원문을 보존하고 `standard-exception-aliases-1`로 다시 계산한다. 후보 선정 전에 개발 점수를 정정하고 같은 규칙을 모든 후속 결과에도 적용한다. 프롬프트/자료/응답은 변경하지 않는다.

해석 제한: E09/E10은 초안 호출에도 해당 접근의 일반 검토 안내가 포함되므로 마지막 단계만 바꾼 순수 요인 실험으로 해석하지 않는다. E01c와 C0는 같은 입력·지침의 반복 대조여서 차이는 모델 변동을 보여준다. 확장 입력의 다중 요인이 함께 바뀐 실험에서 단일 원인을 확정하지 않는다.
