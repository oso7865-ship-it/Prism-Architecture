# ADR-REVIEW-015: 주니어/시니어 설명 모드와 모드별 하네스

> ID: `ADR-REVIEW-015` · 소유: `REVIEW` · 기준: `2026-10-05`

- 상태: `ACCEPTED`
- 근거: 사용자가 2026-10-05 채팅에서 모드 분리를 요청하고 저장 위치(사용자 프로필)·차이 범위(설명·어조·교육적 제안만)·시니어 재작성·범위(백엔드+화면 선택)·유료 평가 최대 600회를 선택했다. 시니어 1차 평가 미달 후 지침 보정·재측정(방안 C)도 사용자가 선택했다.
- 대체하는 ADR: 없음. [ADR-REVIEW-014](ADR-REVIEW-014-grounded-claims-and-repair-guards.md)의 출력·검증·호출 계약을 그대로 두고 모드 축을 추가한다.
- 대체한 ADR: 없음.

## 배경

신입 개발자에게는 문제의 이유와 올바른 패턴까지 설명하는 리뷰가, 숙련자에게는 간결한 리뷰가 맞다. 하나의 지침으로 두 요구를 함께 만족시키면 길이와 어조가 모호해진다. 지적 기준과 출력 계약은 하나로 유지하고 설명 방식만 나눈다.

## 결정

- 모드는 `SENIOR`/`JUNIOR` 닫힌 집합이며 기본은 `SENIOR`다. 사용자 프로필(`users.review_mode`)에 저장하고, 리뷰 시작 시 요청자의 모드를 `review_runs.mode`에 고정한다. 이후 프로필을 바꿔도 이미 접수된 실행과 완료된 결과는 바뀌지 않는다. 모드는 실행 중복 키에 포함되어 같은 입력도 모드가 다르면 별개 실행이다.
- 모드별 별도 하네스: `harness/senior/`와 `harness/junior/`에 서버 소유 지침 11개씩을 둔다. 서버가 payload의 `review_mode`로 선택하며 클라이언트·코드·모델 출력이 경로를 정하지 않는다. 이전 지침은 `evals/review-modes-v1/legacy-current/`에 동결 보관한다. `prompt_version`은 두 모드 문서 전체와 스키마의 해시이고 어느 모드 지침이든 바뀌면 달라진다.
- 모드 간 동일: 출력 JSON Schema·검증·admission 기준(`checks` 문서는 바이트 동일)·호출 최대2회·팀 하루 30회·시스템 입력 24,576byte 한도(최악 조합 시니어 23,452, 주니어 24,083)·원문 비저장. 모드 차이는 지침의 설명 방식(주니어: 이유·구체 입력 예·올바른 패턴·확인 항목, 시니어: 직접·간결)이다. 사용자 제공 문자열은 지침에 들어가지 않는다.
- 평가 후 보정: (1) 두 모드 공통 심각도 기준: 유효 입력에서 틀린 결과·의도 밖 예외·데이터 손실·보안 구멍이 입증되면 ERROR, 특이한 입력·상태가 필요하면 WARNING이며 교육 효과로 올리지 않는다(두 모드 문구 동일). (2) 값 주장 규칙: 계산 값·예외·특수값은 서버 검사 결과나 정확한 타입의 언어 규칙으로 확실할 때만 쓴다. (3) 주니어의 모든 필드는 한 가지 ~요체로 쓴다. (4) 모델이 JSON 모드 플래그를 답에 그대로 싣는 현상(`"type":"json_object"`)은 서버가 최상위의 정확히 그 키·값만 제거한 뒤 기존 strict 검증을 한다. 다른 키·값·중첩은 거부한다. 이는 출력 검증기의 좁은 완화이며 스키마·권한·호출 한도는 바뀌지 않는다.
- API: `PATCH /api/v1/users/me/preferences`(본문 `review_mode`만, 추가 필드 금지, 인증 필요). `GET /users/me`와 리뷰 응답에 모드가 포함된다. 모드가 없는 구형 응답은 SENIOR로 취급하고 알 수 없는 값은 거부한다.
- DDL: migration `0010`이 `users.review_mode`와 `review_runs.mode`(둘 다 기본 'SENIOR', 허용값 CHECK)를 추가한다. downgrade는 모드 데이터가 있으면 거부한다.

## 대안

하나의 지침에 모드 문구만 덧붙이기(예산·일관성 문제), 요청마다 모드 선택(재현·중복 키 복잡), 모드별 출력 스키마(소비자 영향 큼)를 채택하지 않았다.

## 영향과 한계

AI 리뷰는 팀 소유자만 시작하므로 프로필 모드는 시작한 사용자 기준이며 팀 구성원은 소유자 모드의 결과를 본다. 합성 사례 32개·56회 기준 평가이며 통계적 결론이 아니다. 시니어 보정은 같은 사례로 재측정해 과적합 가능성이 있다. 교육 효과 자체는 측정하지 못했다. 주니어는 근거+제안 길이가 시니어의 약 2배다. 화면은 주니어 모드 리뷰의 '이유와 개선 방법'을 기본 펼침으로 보이고 제안 카드는 요약 줄과 중복되는 영향 문장을 상세에서 제외한다. 마이그레이션 0010은 파일만 있고 어떤 DB에도 적용하지 않았다. DB 통합 테스트는 이 환경에서 실행하지 못했다.
