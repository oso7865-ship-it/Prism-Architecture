## 1. 요청·설계·적용

- 요청: 정적 분석·개요 등 전체 화면 용어를 사용자 친화적으로 바꾸고 변경 이력을 표로 제공한다.
- 사전 설계: [작업 계획](../docs/work-plans/2026-09-27_plain-language.md).
- 결과: [전체 변경 이력 표](../docs/USER_LANGUAGE_CHANGELOG.md). 반복 표현·조사·시제 차이는 영역별 대표 표현으로 묶었다.
- 메뉴는 한눈에 보기/코드 점검/AI 리뷰/변경 기록, 버튼은 사용자가 수행할 행동, 오류는 상황과 다음 행동으로 정리했다.
- 로그인·홈·팀·저장소·PR 상세·정적 점검·AI 리뷰·근거·범위·개인 메모·상태 배지·공통 오류·접근성 이름·브라우저 제목을 검사했다.
- 코드 점검은 코드를 실행하지 않는 규칙 검사라고 설명한다. AI 개선 제안과 추가 확인 질문을 구분하고, 제안이 실제 결함으로 검증됐다는 인상을 주지 않는다.
- AI 동의에는 변경·관련 코드, 이전 개인 메모와 점검 요약을 명시한다. 일일 한도 초기화는 UTC 자정과 같은 한국시간 오전 9시로 설명한다. 실패·취소 비용, 전송 한도와 자동 재요청 없음은 보존했다.
- API 키/주소/enum, URL의 tab=static, 권한 분기, 저장 데이터는 변경하지 않았다. 사용자 작성 제목·파일 경로·코드·커밋 해시·이전 AI 자유 서술은 그대로 둔다. CSS·백엔드·의존성을 이번 작업에서 변경하지 않았다.

## 3. 도구·증거·실패 처리

- 브라우저: `mcp__cua_repl.js`, `playwright.domSnapshot/innerText/getByRole/press/selectOption/evaluate`, viewport capability, `screenshot`. 실제 측정은 DOM 읽기만 사용했다. 폼 제출·새 분석·유료 AI 요청 없음.
- 테스트: `npm test -- --run`, `npm run build`. Sandbox의 esbuild 상위 경로 읽기 제한 때문에 승인된 로컬 실행으로 검증했다.
- 초기 테스트의 문구 기대값 불일치 4건은 새 문구에 맞추고 전체 108개를 다시 통과했다. 신규 테스트는 동의·직접 링크 계약을 검증하며 문자열 대체만 확인하는 테스트를 대량 추가하지 않았다.
- 변경 이력 파일 작성 스크립트의 상대 경로 오류 후 소스 적용 상태를 확인하고 절대 경로로 문서를 작성했다. 원본 변경을 다시 일괄 치환하지 않았다.
- 브라우저 기록 선택기는 label locator 실패 후 현재 상태를 읽고 combobox role locator로 선택·결과 변경을 확인했다.
- 캡처 위치: 저장소 밖 `../../audit-artifacts/2026-09-27-plain-language/`. 01-before, 02-login-after-320, 03-code-check-320, 04-code-check-375, 05-code-check-414, 06-code-check-768, 07-code-check-1280, 08-ai-after, 09-team-after 및 responsive-results.json. 공유·다른 PC 이동 시 필요한 캡처를 함께 옮겨야 한다.
