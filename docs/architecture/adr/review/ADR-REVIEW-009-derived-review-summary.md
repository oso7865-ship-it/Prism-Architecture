# ADR-REVIEW-009: 검증된 리뷰 항목으로 사용자 요약 구성

> ID: `ADR-REVIEW-009` · 소유: `REVIEW` · 기준: `2026-09-27`

- 상태: `SUPERSEDED`
- 근거: 사용자가 위임한 품질 안정화 범위에서 관측된 요약/상세 모순을 줄이는 구현 결정.
- 대체하는 ADR: [ADR-REVIEW-008](ADR-REVIEW-008-team-daily-allowance.md). 사용자 결과 summary 구성만 변경하며 일일 한도와 나머지 계약은 유지한다.
- 대체한 ADR: [ADR-REVIEW-010](ADR-REVIEW-010-evidence-first-verified-review.md). 문맥/검증 호출 계약 대체; 요약 조합은 유지.

## 배경

AI가 같은 조건식을 요약과 상세에서 반대로 설명한 사례가 반복 평가에 나타났다. 파일/줄·schema 검증은 자연어 참/거짓 일관성을 보장하지 않는다. 두 번째 모델 호출이나 추론 모드도 비용 증가와 새 오탐 없이 개선된다는 근거가 부족하다.

## 결정

새 리뷰의 summary는 모든 항목의 기존 검증이 끝난 뒤 서버가 issues/questions 건수와 제목 최대3개로 구성한다. SUPPORTED 제안을 먼저, ERROR/WARNING/INFO 순서로 소개하고 동일 중요도에서는 기존 순서를 지킨다. 질문만 있으면 추가 확인할 내용으로 표시하며 확정 결함처럼 단정하지 않는다. 0건은 제공된 범위에서 지적 없음과 검토 한계 확인을 안내한다. 서버는 동작·인과관계를 새로 해석하지 않는다.

모델 응답의 기존3필드 schema(summary/issues/limitations)는 유지하며 summary도 길이·타입·비밀 검사를 받는다. 자유 요약은 새 제품 결과에서 사용하거나 별도 보관하지 않는다. 원문 응답/추론 저장과 추가 외부 호출을 하지 않는다. limitations와 상세의 모델 설명은 유지하며 사실성 보장이 아님을 명시한다.

API result.summary의 문자열 타입과 DB schema는 바꾸지 않는다. 서버 조합 문장은1600자 이내로 제한되고 텍스트로만 렌더링한다. 과거 영속 결과는 그대로 둔다. 출력 지침 해시를 갱신하여 새 요청의 중복 판정과 이력을 이전 버전과 구분한다.

## 유지 계약

008의 팀당 UTC 하루 기본/최대30회·동시1개·실패/취소 소비, 007의 BOUNDED_CODE_V3·관련 문맥/예산·리랭커 기본 OFF, 006의 개인 처리·질문 분리·고정 소스·과거 이력 불변, 근거·가정·권한·연결 세대·취소/lease 검증을 유지한다. 제품은 기존 비추론 모델 설정, 호출1회·재시도0·출력2000토큰·모델60초/전체90초다.

## 대안

지침만 강화해 자유 요약을 유지하는 방식은 동일 모순이 재현되었다. 추가 모델 검수는 호출·시간 계약을 바꾸며 자체 오판도 가능하다. 모델 요약 자체를 없애는 schema 변경은 이번에는 하지 않는다.

## 영향과 한계

결정적 요약은 코드 변경의 자유로운 개괄을 잃는 대신 사용자가 검토할 항목과 실제 표시 결과의 불일치를 줄인다. 제목/상세가 틀린 경우까지 해결하는 것은 아니다. 기존 결과와 새 결과가 서로 다른 요약 형식으로 표시될 수 있다.
