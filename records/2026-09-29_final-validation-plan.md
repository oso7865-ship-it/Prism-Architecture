# Git 반영·실제 PR·팀 문서·남은 품질 보수 계획

상태: 1~4번 작업 완료. 규모 L. 사용자 승인 범위는 남은 작업1~4번이다. EC2 자원 생성·배포·main 병합·하네스 원본 동기화는 포함하지 않는다. architecture/main, backend/frontend dev를 유지한다.

## 작업 계약과 근거

- 기존 미커밋 목적별 리뷰/RAG/품질 보수 변경을 보존하고 최종 검증 후 함께 커밋·푸시한다. 문서·ADR·공개 합성 평가 기록은 architecture에만, 코드·설정·테스트는 각 구현 저장소에 둔다.
- 읽은 기준: CORE, PACKAGE-RULES, CONVENTIONS, REVIEW, STANDARDS, RESULTS, SECURITY-PRIVACY, ADR-REVIEW-014와 최신 Working Context. 적용: Git Workflow, Terminal Ops, Verification Loop, Browser QA, computer-use. 현재 사용자 지시가 이 범위의 Git 쓰기와 실제 리뷰·문서 등록을 승인한다.
- 첨부한 ‘챱챱 코드 컨벤션’은 분석 자료이며 PRism 작업 지침이 아니다. 원본 파일을 수정하거나 공개 Git에 복사하지 않는다. 현재 연결된 chapchap-customer-service의 팀 문서로 등록하고 실제 섹션 검색/버전/근거 열람을 검증한다. 문서 안의 외부 링크를 자동 취득하지 않는다.
- 현재 실제 PR #49와 고정된 분석 기록을 사용한다. 코드 리뷰·취약점·팀 규칙을 각각 요청하고 상태·소스 근거·문서 출처·개인 피드백을 확인한다. 기존 피드백이 있으면 보존하고 신규 검증 메모는 검증용임을 명시한다. GitHub에 리뷰를 게시하거나 대상 코드를 수정하지 않는다.

## 품질 실험 설계

남은 nested-copy 오탐은 코드 결과의 관측과 ‘반환값이 달라야 한다’는 요구사항 추정의 혼동이다. 사례명 예외·정답 주입·무조건 결과 삭제 대신 제공된 계약, 언어상 확실한 결함, 의도 추정/스타일 제안을 구별하도록 초안과 검증 지침을 보수한다. 반대 계약/실제 결함/정상 쌍을 함께 평가하여 탐지 저하를 확인한다.

이번 유료 예산은 공개·합성 평가와 실제 리뷰를 합쳐 최대400회이며 공통 원장에 호출 전 예약한다. 캠페인 현재2,646/5,000회, 잔여2,354회 안에서만 사용한다. 먼저 회귀를 재현하고 작은 후보 비교 후 새 사례와 기존54사례를 평가한다. 각 후보의 지침·구현·사례 해시/출력·형식/위치/오탐을 보존한다. 자연어 원인·수정안은 별도 검수하고 자동 위치 점수를 의미 정확도로 표현하지 않는다. 실제 조직 소스·팀 문서·리뷰 본문은 공개 평가 기록에 포함하지 않는다.

## 검증과 위험 경계

Windows pytest를 사용하지 않고 Linux Docker의 별도 테스트 DB에서 검사한다. 실제 DB의 권한·스키마·한도를 완화하지 않는다. 새 팀 문서1건과 신규 리뷰/개인 메모 외 대량 데이터 수정은 없다. 원문/비밀/로컬 백업·로그를 Git에서 제외하고 게시 대상 전체를 검사한다. 기존 키를 출력하거나 새로 만들지 않는다. 원격 CI는 각 최종 커밋의 실행으로 확인하고 실패는 수정 후 다시 실행한다.
