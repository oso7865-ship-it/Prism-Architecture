# ADR-ARCH-003: 문서 중앙 관리와 구현 저장소 분리

> ID: `ADR-ARCH-003` · 소유: `ARCH` · 기준: `2026-09-28`
> 읽는 때: 저장소 경계·하네스 복원·문서 게시를 변경할 때

- 상태: `ACCEPTED`
- 기록일: `2026-09-28`
- 근거: 사용자 “전체적으로 병합”, “문서파일은 프론트 백엔드에 올라가면 안돼” 지시
- 대체하는 ADR: [ADR-ARCH-002](ADR-ARCH-002-independent-repositories.md)
- 대체한 ADR: 없음

## 배경

구현 저장소의 README·설계·Report·개발 하네스 문서를 아키텍처 저장소에 통합하면서 다른 PC에서도 작업을 재개할 수 있어야 한다.

## 결정

세 저장소 독립성과 코드 소유권, architecture.json의 기준 커밋·논리 경로는 유지한다. 개발 문서·하네스·프로젝트 어댑터·평가 보고서는 records/backend·frontend에 원래 상대 경로와 내용 그대로 보존하고 manifest SHA-256으로 확인한다. 과거 기록의 상대 링크는 원래 구현 저장소 기준이며 기록을 새 성과로 덮어쓰지 않는다.

구현 저장소의 문서는 index 추적을 해제하고 ignore/CI로 재유입을 막는다. 기존 로컬 파일은 삭제하지 않는다. 다른 PC에서는 고정한 아키텍처 clone과 `node scripts/restore-docs.mjs <clone 경로>`로 무시되는 사본을 복원한다. 복원은 고정 Git manifest·해시·경로를 확인하며 수정된 로컬 파일을 덮어쓰지 않는다. 코드 실행·테스트·CI는 문서 복원에 의존하지 않는다.

제품이 읽는 리뷰 지침·평가 fixture는 .prompt 실행 리소스로 코드 저장소에 남긴다. 내용·prompt_version·전송 정책은 이관 때문에 변경하지 않는다. 설계·보고서·개발 지침을 확장자만 바꿔 코드 저장소에 남기지 않는다. 런타임은 개발 하네스나 아키텍처 저장소를 읽지 않는다.

## 대안

ignore만 추가하면 추적 중인 문서가 계속 올라간다. 문서 삭제만 하면 재개와 근거가 소실된다. 새 main/dev의 현재 파일 트리에서 분리하며 과거 Git 이력은 재작성하지 않는다. 이전 커밋에는 당시 문서가 남는다.

## 영향과 한계

하네스 원본 동기화는 계속 보류하고 게시 장소만 변경한다. 구현 CI는 독립 코드/비밀/문서 유입 검사를 수행하고 중앙 CI는 현재 설계·문서 보존 검사를 수행한다. 로컬 문서 변경은 중앙 저장소에 별도 반영해야 한다. 코드 병합은 모델 의미 품질 PASS나 공개 배포가 아니다.
