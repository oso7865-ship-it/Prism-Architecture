## 범위와 판단

[사전 설계](../docs/work-plans/2026-09-27_layout-alignment.md)에 따라 로그인, 홈, 저장소/변경 요청 목록, 팀 설정, 상세 요약/코드 점검/AI 리뷰/변경 기록을 검수했다. 계정 메뉴는 직전 작업의 단일 컴포넌트 배치를 유지했다. Product Design audit의 실제 화면 증거 수집을 병행했다.

320px에서 확인한 주요 문제는 고정된 들여쓰기와 좁은 영역에서도 유지되는 다열 배치였다. 목록 제목과 배지의 시작 위치가 어긋났고, 코드 점검 아이콘이 제목 위로 분리되었으며, 4열 탭의 글자가 쪼개졌다. 기능과 색상 체계를 유지하면서 이 배치 규칙을 수정했다.

## 변경 이력

| 위치 | 이전 문제 | 변경 |
|---|---|---|
| 코드 점검·AI 제목 | 아이콘·제목·보조 정보가 각각 줄바꿈 | SectionHeading으로 묶음, 좁은 영역에서는 보조 정보를 제목 아래 정렬 |
| 펼침/접힘 행 | 네이티브 삼각형과 아이콘 간격·기준선 혼재 | DisclosureSummary로 공통화, 우측 SVG 화살표와 44px 이상 조작 영역, native details 유지 |
| 모바일 작업 메뉴 | flex와 grid 설정 충돌, 긴 가운데 메뉴에 공간 부족 | 실제 3열 grid, 가운데 메뉴에 더 넓은 폭, 아이콘과 이름의 동일한 간격 |
| 홈 최근 변경 요청 | 상태와 화살표가 제각각 다음 줄로 이동 | 번호·제목·상태·화살표 칸 분리, 좁으면 상태를 제목 바로 아래 배치 |
| 저장소 카드 | 상태의 임의 margin, 관리 버튼의 들여쓰기 | 아이콘/이름/상태 grid, 관리 행의 좌우 간격과 높이 통일 |
| 저장소 연결 | 절대 위치 버튼에 맞춰 제목 공간을 미리 비움 | 정상 문서 흐름 안의 펼침 행, 모바일 연결 폼 한 열 |
| 변경 요청 목록 | 배지 고정 들여쓰기, 긴 필터 옵션의 폭 부족 | 상세 열·모바일에서는 본문 아래 상태 정렬, 상태 선택 폭 확대 |
| 팀 멤버 | 배지 때문에 사용자명이 과도하게 줄바꿈 | 아바타/이름/역할을 grid로 묶고 좁을 때 역할을 이름 아래 표시 |
| 계정 검색·초대 | 2개 요소에 3열, 버튼 폭/바닥선 불일치 | 입력+150px 버튼 2열, 좁을 때 같은 폭의 한 열, 계정 확인과 역할 사이 여백 |
| 상세 탭·변경 기록 종류 | 좁은 화면에서 단어가 쪼개짐 | 상세 패널 자체가 좁으면 2×2 배치, 탭 높이44px 유지 |
| 점검/리뷰 숫자 요약 | 긴 설명 때문에 값 높이가 어긋남 | 넓을 때 값 바닥선 일치, 좁을 때 라벨과 값을 한 행에 정렬 |
| AI 카드·메모 | 중첩 테두리/여백으로 읽기 폭 감소, 펼침 상태 위치 혼재 | 좁을 때 바깥 질문 영역 여백 축소, 메모 상태·설명·입력의 계층 정리 |
| AI 파일 링크·개수 | 긴 파일명과 줄 번호가 잘게 쪼개지고 개수가 홀로 내려감 | 파일명/목적지 분리, 줄 번호 묶음 유지, 제목과 개수 grid |
| 로그인·안내 | 단계 번호/설명의 간격, 줄바꿈 숨김 시 붙는 문장 | 단계 번호/본문 grid, 모바일 여백, 홈 안내 제목의 단어 사이 공백 보존 |

고정 margin으로 맞추던 규칙을 제거했다. 전역 CSS의 관련 배치는 마지막 Layout ownership 구역이 소유하며, 두 공통 컴포넌트는 `src/shared/ui`에 있다. API, 라우트, 코드 원문, AI 입력/정책은 변경하지 않았다.

홈, 팀, 저장소 연결 폼, 코드 점검, 펼친 AI 결과, 로그인 각각에서320/375/414/768/1280px 관측을 기록했다. `responsive-results.json`의30개 결과에서 문서 폭이 viewport를 넘지 않았으며 주요 입력·버튼·펼침 행의 가로 넘침도 없었다.

- 모바일 홈 최근 요청 제목/배지 x=84px로 일치. 저장소 이름/배지 x=88px로 일치.
- 코드 점검 탭은320px에서 각109.5×44px, 375px137×44px, 414px156.5×44px. 작은 상세 패널의2×2 배치로 글자 쪼개짐을 없앴다.
- 팀 폼은768/1280px에서 입력과 버튼의 바닥선이 일치하고 두 버튼 모두150px. 모바일에서는235/290/329px의 전폭 버튼으로 전환했다.
- AI 코드의 긴 줄은 `pre` 내부에서만 스크롤한다.320px에서 코드 상자160px/내용884px, 문서305px로 페이지 넘침 없음.
- native details는 Enter로 열고 닫았다. 계정 메뉴와 로그인 버튼 조작, 상태 선택, 검색, 코드 조회를 실제 브라우저로 검증했다.
