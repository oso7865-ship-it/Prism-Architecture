# 제한 문맥 검색 개선과 리랭커 비교

- 규모 L, backend dev / architecture main. 사용자 승인: 앞서 제안한1~3단계 전체(문맥 수집 개선, 동일 후보 리랭커 비교, 효과 확인 후 도입). terminal-ops와 quality-gate를 적용한다.
- 읽은 계약: CORE, PACKAGE-RULES, CONVENTIONS, REVIEW, SECURITY-PRIVACY, ADR-REVIEW-006. 기존 미커밋 기능·결과를 보존한다.
- 설계: 고정 HEAD/지원 언어/비밀·제외 경로 필터를 유지한다. 변경 파일의 함수/메서드 경계를 활용하고, import·식별자·경로 관계로 제한된 후보 파일을 찾는다. 후보는 최대12파일 읽기, 최대24개 코드 구간, 최종 관련 파일2개/전체24KiB. 후보 구간은 최대80줄이다. 저장소 전체 검색이나 완전한 호출 그래프를 주장하지 않는다.
- 선택: 동일 후보에 규칙 점수와 로컬 모델 점수를 비교한다. 변경 diff는 선택 대상이 아니므로 제거하지 않는다. 리랭커는 별도 CPU 컨테이너로 격리하고 호스트 loopback만 노출한다. 모델 파일은 공식 저장소의 고정 revision/sha256, 원격 코드는 실행하지 않는다. 기본 모델은 cross-encoder/ms-marco-MiniLM-L6-v2의 공식 ONNX이며 영어 검색 학습/코드 평가 한계를 기록한다.
- 서비스: 모델 자동 다운로드를 요청 경로에 넣지 않는다. 입력 개수/byte/token·동시성·CPU/메모리·시간 제한을 두며 코드/쿼리 로그와 영속 저장은 금지한다. timeout/비정상 점수/서비스 중단 시 규칙 선택으로 돌아가고 coverage에 사유를 남긴다. 기능 기본 OFF에서 시작한다.
- 버전: 검색 계약 변경은 ADR-REVIEW-007과 BOUNDED_CODE_V3으로 기록한다. 결과에는 선택 방식·후보 수·누락 사유·모델 revision을 남긴다. 사용자 코드 내용이나 원문 질의는 저장하지 않는다. 인증/팀/연결 세대·외부 전송 전후 검증·DeepSeek1회 한도는 유지한다.
- 평가: 실행 전 고정하는 다중 파일 합성 corpus12개(Java/Python/JS/TS 각3개)에 정답 근거 줄과 리뷰 기대 결함을 지정한다. 모델용 질의에 정답/기대 결함을 주지 않는다. 규칙/리랭커에 동일 후보/선택 예산을 제공한다. 실제 조직 코드 전송은 하지 않는다.
- 채택 기준(측정 전): 후보 정답 포함률, 최종 정답 근거 포함률, 무관 문맥, 변경 줄 보존을 분리한다. 리랭커는 규칙보다 최종 근거 포함 사례2개 이상 개선하고 기존 성공을 잃지 않아야 한다. warm p95 추가 추론2초 이하, 최종입력24KiB, 안전성/장애 복귀 검증 PASS가 필요하다. DeepSeek 비교는12사례×2방식 각1회, 최대24 유료 호출/재시도0. 구조 오류·불필요 질문·기대 결함 누락이 규칙 대비 악화되면 기본 OFF를 유지한다. 승인된 비교를 넘어 추가 유료 호출은 하지 않는다.
- 위험/승인 근거: 현재 전체 단계 지시가 필요한 로컬 의존성·모델 다운로드/컨테이너 실행과 제한 유료 비교의 근거다. 실제 실행은 도구 권한 심사를 따른다. 비밀은 출력하지 않으며 외부 설치는 공식 PyPI/공식 모델 데이터만 사용한다. 기존 Windows 네이티브 장애 때문에 모델/DB 통합검증은 Linux 컨테이너를 사용한다.
- 검증: 순수 회귀 → 제한 네트워크/소스/랭킹 실패 회귀 → 실제 로컬 모델 비교 →24회 이내 DeepSeek 비교·수동 의미 검수 → Linux backend통합 검증/문서 검사 → Job유휴 확인 후 로컬 반영.
- 제외: 벡터 DB/저장소 영속 인덱스, 전체 저장소 전송, 외부 리랭커 사업자, DB/API schema 변경, 프론트 재설계, 커밋·push·배포.
- 롤백: 리랭커 OFF 시 규칙 선택을 유지한다. V3 자체 문제는 신규 접수 중지/진행 Job확인 후 이번 문맥 구현만 복구한다. 이전 결과는 재작성하지 않는다.
