## 추가 설계: 합성 평가에서만 추론 옵션 비교

- 관측: 새 acceptance-v2 36회에서 구조 오류는 없지만 Python range의 0 step 결함을 2회 놓쳤고, 같은 줄의 중복 지적은 자동 채점이 놓쳤다. 문구 추가만으로 해결됐다고 판단하지 않는다.
- 동일 모델·동일 현재 지침으로 실패 사례와 정상 반례, 관련 파일·유효 질문 사례 12개를 미리 고정하고 추론 low 옵션을 2회씩 비교한다. 비교 대상은 개발용 사례이며 독립 정확도 측정으로 부르지 않는다.
- scripts 전용 provider를 사용한다. 제품 provider/API/한도/시간제한은 바꾸지 않는다. 실험만 thinking enabled, reasoning_effort low, max_tokens 4096, 90초, 재시도0을 적용하고 실행 메타데이터에 남긴다.
- 추론 원문은 반환·출력·저장하지 않는다. 최종 답변에 기존 검증을 그대로 적용하고 토큰 총량·시간·수동 의미 판단을 비교한다. 동일 전역 승인 기록으로 시도를 차감한다.
- 1차 24회에서 의미 오류가 줄어들어도 즉시 서비스 기본값을 바꾸지 않는다. 시간·응답 종료·전체 회귀 및 별도 설계 결정을 거쳐야 하며, 제한된 실험의 유효성도 보고한다.

## 추가 설계: 검증 결과로 사용자 요약 조합

- 언어 계약 수정 후 자동36/36에도 JS 단락 조건의 summary와 상세가 반대인1건이 남았다. 동일 결함을 두 번 자유 서술하게 두는 구조를 줄인다.
- ADR-REVIEW-009: 결과 summary는 서버가 검증 완료된 issues/questions의 건수와 우선 제목 최대3개로 조합한다. 확정 제안과 추가 질문은 분리하며 질문을 결함으로 승격하지 않는다. 0건은 검토 범위에서 지적 없음으로만 설명하고 안전 보증을 하지 않는다.
- 모델 summary는 기존 strict schema/비밀 검사를 통과해야 하지만 새 결과의 표시/저장에는 사용하지 않는다. 허용 필드·응답 크기 검증을 완화하지 않고 원문 summary도 추가 저장하지 않는다. 한계 limitations와 상세는 기존대로 유지한다.
- API/DB schema는 그대로이며 과거 결과를 수정하지 않는다. 출력 지침 변경으로 prompt 버전을 올려 새 요청과 구분한다. 제품 경로 테스트에 모순 요약·질문만 있음·0건·우선순위·크기·HTML/비밀 거절을 포함한다.
- 최종 지침으로 기존 회귀66회와 language/builtin 회귀 각36회를 확인한다. builtin 원래 실행은 변경 전 독립 소규모 평가로 보존하고 이후 실행은 회귀다. 실제 PR 재호출은 추가로 하지 않는다.
