# ADR-REVIEW-010: 필수 문맥 보존과 두 단계 리뷰

> ID: `ADR-REVIEW-010` · 소유: `REVIEW` · 기준: `2026-09-27`

- 상태: `SUPERSEDED`
- 근거: 사용자 개선안1~5 구현 및16KiB 확대 지시.
- 대체하는 ADR: [ADR-REVIEW-009](ADR-REVIEW-009-derived-review-summary.md). 문맥 예산/선택과 검증 호출 계약을 변경한다.
- 대체한 ADR: [ADR-REVIEW-011](ADR-REVIEW-011-empty-recheck-and-source-view.md). 빈 초안 처리와 코드 열람을 변경한다.

## 배경

파일별 첫 구간만 남기는 선택 방식은 리랭커가 설명/헤더를 우선할 때 직접 호출된 메서드를 버린다. 기존24KiB 예산을 소진하지 않아도 발생했다. 한편 형식과 줄 번호 검증은 정상 코드 지적이나 잘못된 결과 설명을 차단하지 못했다.

## 결정

BOUNDED_CODE_V4는 patch/파일 JSON16KiB, 전체 코드 JSON48KiB 상한이다. 변경 파일8, 후보 파일12, 후보 구간24, 관련 파일 최대4다. 함수별 변경 구간에서 호출/식별자·import 신호를 모으고 구문상 직접 호출 이름과 정의가 일치하는 후보를 우선 보존한다. 함수별 후보를 교대로 배정하며 같은 파일의 구간을 합친다. 리랭커는 보조 순위이며 보호 구간을 제거할 수 없다. 전체 예산 초과/불완전 함수/구문 미확보는 기록하며 전체 프로그램 분석으로 표시하지 않는다. 구간 최대160줄, 파일 취득200KB·시간20초 경계와 비밀/제외 경로·고정 HEAD 검사는 유지한다.

초안을 기존 strict schema로 검증한다. 지적이 있으면 같은 입력과 초안을 별도 모델 호출로 재검수한다. 원 항목마다 KEEP/REVISE/DROP을 하나씩 반환하며 구체적 발생 조건·결과·반례·호출부 가드·불필요 질문·중복을 확인한다. 새로운 지적과 파일/대표 줄 변경은 허용하지 않는다. 수정도 원 schema/제공 근거 검증을 거친다. 초안0건이면 검증 호출을 생략한다. 검증 실패는 전체 FAILED이며 미검증 초안을 성공으로 표시하지 않는다. 결과에는 검증 여부와 유지/수정/제외 건수만 추가한다. 원문/초안/검증 자유 응답은 저장하지 않는다.

실행당 최대2회, 회당60초·출력2000토큰, 전체150초·재시도0. 각 전송 직전 권한/연결 세대/취소/lease 검사와 call_attempts 예약을 커밋한다. DB CHECK를0..2로 완화하고 관측 토큰을 합산한다. 두 번째 실패에도 첫 번째 관측 사용량은 보존하며 불확실 청구 여부를 표시한다. 일일30회는 여전히 접수 횟수로 최대 외부 호출60회가 가능하다.

## 유지 계약

리랭커 기본 OFF, 고정 source SHA, 원문 미보관·대상 코드 실행 금지, 근거/질문 분리, 개인 메모와 소스 접근 권한, 팀 하루30회·동시1개·실패/취소 소비, 과거 결과 불변,009의 검증 결과 기반 요약을 유지한다. 하네스와 검증 지침/schema 변경은 prompt 버전에 포함한다.

## 대안

8KiB만16KiB로 올리면 전체24KiB에서 파일 간 경쟁이 심해진다. 리랭커 교체만으로 구조적 누락을 해결할 수 없다. 같은 호출 안의 자기 점검만으로는 이전 의미 오류가 지속되어 별도 검수를 채택한다. 모든0건까지 재호출하면 비용이 늘어나므로 이번에는 지적 검수에 집중한다.

## 영향과 한계

입력/호출 비용과 지연 상한이 늘어난다. 검증기도 같은 모델이므로 공통 오판과 과도한 제외 가능성이 있다. AST 이름 일치는 동적 호출/alias/상속의 완전한 해석이 아니다. 보호 후보도 전체 한도 내에서만 제공하며 누락을 metadata로 드러낸다. 공개 실제 PR에서 파생한 최소 재현 gold와 기존 회귀에서 결함 검출·정상 오탐·상세 의미·지연/토큰을 따로 측정한다. 채택 자체는 품질 통과가 아니다.
