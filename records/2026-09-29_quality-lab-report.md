## 트러블슈팅: 마지막 재검토가 결함을 복구하지 못함

**어디서:** 기존 `ca-before` 재현2회, [1회차 초안](quality-evaluations/quality-lab-20260929/calls/bridge-C0-e039b4bf0e2d-r1-draft.json) → [재검토](quality-evaluations/quality-lab-20260929/calls/bridge-C0-e039b4bf0e2d-r1-verify.json) → [최종](quality-evaluations/quality-lab-20260929/results/bridge-C0-e039b4bf0e2d-r1.json).

**무엇/어떻게:** 초안은 변경10줄을 지적했으나 `or`가 빈 문자열을 None으로 바꾼다고 설명했다. 재검토는 MISSING_CONTRACT로 DROP했고 최종 지적은0건이었다. 같은 패턴이2회 재현됐다.

**왜:** `x or y`는 무조건 불리언/None으로 변환하지 않는다. 해당 입력에서는 오른쪽 빈 문자열이 그대로 남으며, None만 복원하는 merge 로직을 통과해 빈 문자열이 반환되는 것이 실제 결함이다. 초안의 위치 적중은 정확한 원인 설명을 뜻하지 않는다. 검증 단계는 틀린 초안 제거는 수행하지만 제거 후 원래 코드/계약의 실제 결함을 새로 작성하지 못한다.

**이번 대응:** 잘못된 설명을 그대로 살리는 변경은 하지 않았다. 호출별 초안/결정/최종·위치 누락을 모두 보존했고, 이를 전체 품질 미통과의 재현 가능한 회귀 사례로 고정했다. 지표 `verifier_induced_miss=2`는 '위치 적중 후보가 최종에서 사라짐'을 뜻하며 **정확한 설명을 가진 참 결함을 검증기가 잘못 지웠다는 뜻으로 해석하면 안 된다.**

**다음 해결 실험:** 초안 기각 이후 해당 변경·호출·계약을 대상으로 새 주장을 작성하는 제한적 재검토와, 주장별 실제값/요구값/수정 후 정상 경로 보존 검증을 비교한다. 같은 틀린 초안을 KEEP하도록 강제하지 않는다. 단순한 언어 연산은 허용된 구문에 한한 결정적 검사로 보조하고, 분석 대상 임의 코드 실행은 별도 격리 설계 없이 도입하지 않는다.

## 평가 도구 자체의 문제와 수정

1. Windows 기본 인코딩으로 한글 승인 원장을 읽는 테스트1건이 실패했다. UTF-8을 명시했고 재검증했다. 제품 장애는 아니다.
2. `java.lang.NullPointerException`을 `NullPointerException`과 다르게 채점했다. 후보 선정 전에 알려진 표준 예외 별칭만 정규화하고, 원문과 `original_strict_metrics`를 보존했다. [정정 기록](quality-evaluations/quality-lab-20260929/scoring-erratum.json)의14개 평가가 영향을 받았다. 임의 예외의 마지막 이름만 같다고 합치지 않는다.
3. 제품 대조군에는 기존 재현12평가가 추가된다. 후보36평가와 직접 비교하지 않도록 표를 새 합성/기존 재현으로 분리했다.
4. 마지막 Windows 오프라인 회귀 실행에서 `access violation` 진단이 출력됐다. 뒤에24 passed와 종료0이 나왔지만 신뢰 가능한 검증으로 채택하지 않았다. 기존 Linux 이미지로 네트워크 없이 읽기 전용 마운트해24개를 다시 실행했고2.17초에 경고 없이 통과했다. 첫 Docker 시도는 호스트 `.venv`가 이미지 환경을 가려 pytest를 찾지 못했으며, `/workspace`로 마운트하고 `/app/.venv/bin/python`을 명시해 해결했다. 이후 이 평가의 회귀 테스트도 Linux에서 실행한다.

## 채택 결론과 다음 우선순위

자동 채택 후보 **없음**. 기존 제품 지침/추론 설정과 팀 하루30회·리뷰당 최대2회는 유지한다. 이번 개선은 재현·예산·채점·단계별 실패 추적 체계와, 효과가 없는 접근을 걸러낸 실험 근거다. 서비스 답변 품질이 해결됐다고 보고하지 않는다.

1. **기각 후 재검토:** 잘못된 설명을 삭제한 뒤 실제 결함을 다시 찾도록 평가한다.
2. **수정안까지 평가:** 위치·반환값 점수 외에 제안이 원래 계약을 보존하는지 독립 기준을 마련한다.
3. **자료 현실화:** 더 큰 호출 관계와 실제 팀 문서가 있는 PR, 언어별 정상/결함 쌍, 독립 사람 라벨을 늘린다. 작은 합성 점수로 일반 품질을 판정하지 않는다.
4. **문맥은 필요에 따라:** 무조건 많은 코드·문서보다 호출부·타입·요구 동작처럼 판단에 필요한 정보를 근거와 함께 선택한다. 선택 단계와 최종 추론 단계의 오류를 별도로 본다.

최소 호출 조건을 이미 충족했고 후보가 채택 기준을 넘지 않아 이 배치를 종료했다. 남은3,569회를 같은 설정의 반복으로 소모하지 않았다.

## 재현과 기록 위치

backend 폴더에서 기존 Linux 테스트 이미지로 검증한다. 호스트 `.venv`가 Linux 환경을 가리지 않도록 `/app`에 마운트하지 않는다.

```powershell
$labSource = (Get-Location).Path
docker run --rm --network none --memory 1g --cpus 2 --mount "type=bind,source=$labSource,target=/workspace,readonly" --workdir /workspace --env PYTHONDONTWRITEBYTECODE=1 --env PYTHONPATH=/workspace prism-review-tests:local /app/.venv/bin/python -m pytest tests/test_quality_lab.py tests/test_recall_oracles.py -q -p no:cacheprovider
.venv/Scripts/python.exe -m ruff check scripts/quality_lab*.py tests/test_quality_lab.py
.venv/Scripts/python.exe -m scripts.quality_lab_report --root ../prism/records/quality-evaluations
```

실제 모델 실행 순서는 `quality_lab_runner --mode development`, 점수 정정 `quality_lab_rescore`, `quality_lab_runner --mode holdout`, `quality_lab_adaptive`, `quality_lab_bridge`다. 모두 `python -m scripts.<이름>`으로 실행하며 네트워크 실행에는 `--root ../prism/records/quality-evaluations --execute`를 명시한다. API키는 기존 로컬 `.env`에서 읽으며 문서/원장에 저장하지 않는다.

동일 ID의 완료 결과는 재사용하고 중단 중 예약된 요청은 자동 재호출하지 않는다. 같은 실험을 새 유료 반복으로 만들려면 새 실험 식별자/고정 설정/예산을 설계해야 한다. 오래된 평가 CLI의3,000회 가정과 섞어 실행하지 않는다. 회로 차단·원장 잠금을 우회해서 숫자를 채우지 않는다.
