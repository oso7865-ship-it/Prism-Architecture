# 패키지 문서 템플릿

> ID: `PACKAGE-TEMPLATE` · 소유: `documentation` · 기준: `v0.1.0 / 2026-09-25`
> 읽는 때: 새 패키지 문서를 추가/분리할 때

새 문서에는 아래 항목만 채운다. 기존 공통 기준을 통째로 복사하지 않는다. 실제 소비자가 없는 빈 패키지를 템플릿 때문에 만들지 않는다.

```text
# <패키지명>: <한 문장 책임>
ID: <고유 ID>
소유 코드 경로: <한 패키지/명확한 범위>
읽는 때: <작업 종류>

## 책임과 제외
무엇을 소유하고 무엇을 다른 도메인에 위임하는가.

## 실제 파일과 역할
파일 목록, 허용/금지 책임. 아직 미구현이면 명시.

## 공개 계약
입력/출력, 실패, 의존하는 다른 도메인의 api.py.

## 상태·데이터·정책
이 패키지가 유일하게 소유하는 내용만 정의.

## 변경/실패 시 동작
중복·재시도·권한 철회·자원 초과 처리.

## 필수 테스트
정상, 거부, 실패, 경계, 소유권 침범을 확인하는 기준.

## 필요할 때만 읽는 관련 문서
최소 링크. 재귀적 전체 읽기 지시 금지.
```

문서 분할은 약 6,000~8,000자를 넘거나 독립 변경 사유가 두 개 이상일 때 검토한다. 숫자는 토큰 수가 아니고 강제 줄이기 기준도 아니다. 완전한 계약을 없애면서 작은 파일만 만드는 것은 금지한다.

새 문서를 추가하면 INDEX, context-map.json, doc ID registry를 함께 바꾸고 validate_docs를 실행한다. 변경에 영향을 받지 않는 정책 복제본을 만들지 않는다.
