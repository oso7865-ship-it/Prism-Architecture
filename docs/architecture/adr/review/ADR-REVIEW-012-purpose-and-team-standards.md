# ADR-REVIEW-012: 리뷰 목적 분리와 팀 문서 검색

> ID: `ADR-REVIEW-012` · 소유: `REVIEW` · 기준: `2026-09-29`

- 상태: `ACCEPTED`
- 근거: 바이브 코딩 사용자의 코드 리뷰·취약점 탐지와 팀 컨벤션/패키지 문서 RAG를 모두 구현하라는 사용자 승인.
- 대체하는 ADR: 없음. ADR-REVIEW-011의 코드 취득·검증·소스 열람 계약을 유지하면서 확장한다. CORE의 기존 RAG 제외 범위는 이번 명시적 요구로 변경한다.
- 대체한 ADR: 없음.

## 배경

한 종류의 AI 답변에 코드 품질·보안·팀 취향을 섞으면 판단 목적과 근거가 모호하다. 사용자가 팀 문서에 근거한 컨벤션/패키지 구조 검사와 취약점 탭을 요청했다.

## 결정

CODE, SECURITY, STANDARDS 목적을 별도 리뷰 실행·이력·멱등 키로 저장한다. 팀의 하루30회·동시1개·리뷰당 최대2회 예약은 목적 전체 합산이다. 기존 실행은 CODE이며 결과를 재작성하지 않는다.

standards 도메인이 저장소별 문서·불변 버전·섹션 인덱스·적용 경로/예외·구조화 규칙을 소유한다. 문서 저장·변경·삭제는 owner, 열람은 member. 리뷰가 사용할 활성 버전 ID를 요청 시 고정하며 외부 전송 직전에도 삭제/비활성화 여부를 확인한다. 버전 교체는 이미 동의한 실행의 내용을 바꾸지 않는다.

Markdown/text 64KiB, 최대8문서/저장소·20버전/문서. 비밀 의심 패턴과 비텍스트 입력은 거부한다. 원문은 비공개 DB 보관이라는 별도 동의 범위를 UI에 표시한다. 삭제는 모든 버전/섹션 제거이며 기존 리뷰의 원문 열람은 불가능해진다.

RAG는 경로 필터 → 모든 필수 섹션 확보 → BM25 어휘 검색 → 12KiB 문맥 구성 → LLM → 섹션 ID/적용 파일/코드 줄 검증이다. 임베딩·리랭커 추가 없이 초기 비용을 제한한다. 필수 섹션이 예산을 넘으면 축약을 요청하며 일부만 전송한 성공으로 처리하지 않는다. 선택되지 않은 섹션 수·선택 방식·버전을 결과에 남긴다. 문서는 시스템 프롬프트가 아니며 실행/네트워크 도구를 제공하지 않는다.

정해진 이름·금지 import·경로 배치는 제한된 선언형 검사로 전체 적용 규칙을 확인한다. 의미적 구조 위반은 코드와 인용 규칙을 함께 읽는 AI 판단이다. 전체 저장소 구조 검사와 PR에서 제공한 범위 검사를 혼동하지 않는다.

취약점 탭은 보안 규칙 탐지와 보안 전용 AI 리뷰를 구분한다. 모델은 관찰 가능한 공격 입력/권한 경계/위험 동작과 영향의 근거를 요구받는다. 보안 규칙의 비밀 원문은 AI에 전달하지 않는다. 탐지0건은 안전 판정이 아니다.

## 대안

전 문서를 매번 보내면 비용·지연·규칙 충돌이 늘고, top-K만 사용하면 필수 규칙이 사라질 수 있다. 벡터 DB와 리랭커를 바로 추가하는 대신 제한된 문서 수에서 경로+어휘 인덱스로 시작한다. 의미 검색이 필요한 사례를 평가한 뒤 확장한다.

필수 섹션도 어휘 일치도 없는 경우에는 적용 경로가 맞는 문서에서 동일 입력 예산 안의 섹션을 선택한다. 선택 방식과 누락 수를 표시하며 언어 간 의미 검색으로 설명하지 않는다. 반드시 검토해야 하는 문서는 사용자가 필수로 지정한다.

## 영향과 한계

문서 원문 저장과 두 테이블이 추가된다. 문서 삭제·버전 고정·인용 오류 처리가 필요하다. 어휘 검색은 표현이 다른 규칙을 누락할 수 있고 AI의 보안 판단은 코드 실행·전체 데이터 흐름 검증이 아니다. 문서가 잘못되거나 낡으면 좋은 인용만으로 답변이 올바르다고 보장할 수 없다.
