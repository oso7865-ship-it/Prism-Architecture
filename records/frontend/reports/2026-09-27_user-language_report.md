## 0. 검수 범위 확인

- 외부 플러그인 절차: Product Design audit의 실제 화면 캡처·관측·보고 절차를 적용했다.
- 요청: 내부 컬럼·상태 코드가 사용자에게 그대로 표시되는지 전체 표시 경로를 점검한다.
- 확인 대상: `src/**/*.vue`의 텍스트 바인딩, auth API 오류 경계, 분석/활동/개인 기록 사전, 백엔드 상태·제외 사유 발행부.
- 사전 설계: [작업 계약과 체크리스트](../docs/work-plans/2026-09-27_user-language.md).
- 현재 계정에 없는 상태는 API fixture와 실제 Vue SSR 렌더를 사용했다. 이 검증을 실서비스에서 오류를 일으킨 것으로 표현하지 않는다.
- 화면 검수는 사용자 문구에 초점을 맞췄다. 전체 기능 E2E, 실제 휴대폰, 스크린리더, 200% 확대, 새 OAuth 인증, 권한 변경·초대 발송·유료 AI 실행은 이번 범위가 아니다.
- 서버가 반환하는 JSON 키/URL/폼 값은 유지한다. 화면 텍스트·접근 가능한 안내와 다른 층이다.

## 1. 발견 사항과 수정

| 위치 | 변경 전 문제 | 적용 결과 | 영향 |
|---|---|---|---|
| 공통 상태 배지 | 미등록 값 원문 노출, `RUNNING`을 항상 동기화로 표현 | 알 수 없는 값은 상태 확인 필요. 동기화 화면만 동기화 중, 공통은 진행 중 | 중간 |
| PR 활동 | GitHub의 APPROVED/CHANGES_REQUESTED 등을 직접 표시 | 승인됨/수정 요청됨/의견 남김/작성 중/리뷰 효력 해제됨. 커밋·대화 종류별 안내 | 중간 |
| 정적 분석 | 제외 사유·오류·중요도 원문 fallback, 미등록 상태 빈칸. 알 수 없는 확신·위치를 낮음/파일 전체로 추정 | FILE_SIZE_LIMIT 번역 보완. 상태·범위·중요도·확신·규칙 평가의 미확인은 명확하게 안내 | 중간 |
| AI 검토 범위 | 새 SYNTAX_PARTIAL/CONTEXT_UNAVAILABLE와 미등록 코드가 문맥 제한에 노출 | 한국어 사유. 문맥 제한은 참조 id 대신 해당 파일 경로 표시. 미등록 사유도 한국어 안내 | 중간 |
| 오류 경계 | native Error.message의 네트워크·JSON 예외가 화면에 노출 가능 | 앱이 작성한 UserFacingError만 직접 표시, 다른 예외는 연결 확인 안내 | 중간 |
| 팀/계정 | 소유권 확인창의 ADMIN, 숫자 ID 중심 계정 메뉴, 이름 미기록을 비활성으로 단정 | 관리자, GitHub 계정 연결됨, 이름 미확인 멤버. 기존 초대의 번호는 사용자명 미기록 설명과 함께 구분용으로 제공 | 낮음 |
| AI 개인 처리 기록 | 미등록 상태가 빈칸, 잘못된 상태로 저장할 수 있음 | 처리 상태 확인 필요. 유효한 상태를 선택해야 저장 가능 | 낮음 |
| 진단 정보·날짜 | 일반 영역의 내부 버전, 잘못된 날짜의 Invalid Date | 실행 정보 펼침 영역에 이름과 함께 보관, 시간 정보 확인 필요 | 낮음 |

사전 조회는 `Object.hasOwn`으로 제한하여 `constructor`, `toString`, `__proto__`가 사전 상속 프로퍼티로 해석되지 않는다. 같은 fallback을 함수 검사뿐 아니라 실제 컴포넌트 렌더에서도 확인했다.

파일 경로, 사용자 작성 PR 제목, 코드 속 변수명, 규칙 번호, 커밋 SHA, 모델명은 원문의 의미가 필요하므로 유지했다. AI의 f1/c1은 변경 파일/관련 파일이라는 설명이 붙은 참조 번호다. 과거 AI 결과의 자유 서술은 재작성하지 않았다.

## 4. 판정·남은 제한

- Verification Loop: PASS. 타입·빌드·106 tests·계약·범위 확인. 별도 lint 명령은 프로젝트에 없음.
- UI/UX Gate: 문구 범위 PASS. 상태의 한국어 이름과 미확인 표현, 오류 복구 안내, 텍스트 상태 배지, 기본 접힘 진단 정보, 기존 파란색 스타일 유지.
- UI-F01/F02/F04: 오류를 가짜 성공으로 바꾸지 않음, fixture는 tests에서만 사용, 로딩/빈 결과/오류를 구분. 저장·권한·초대 전송 관련 동작 검증은 변경하지 않아 N/A.
- 최종 판정: 이번 **사용자 표시 문구 범위 PASS**. 전체 제품 출시/접근성 적합성/AI 품질 인증을 의미하지 않는다.
- 기존 초대 API는 대상 GitHub 숫자 번호만 제공한다. 향후 사용자명 저장·응답 계약을 추가하면 초대 목록도 이름 중심으로 개선할 수 있다. 현재 이름을 임의 추정하지 않았다.
- PR 코드/AI 자유 서술에 있는 `user_id`, `READ_COMMITTED` 같은 프로그램 용어는 리뷰 대상 내용이다. 앱 내부 컬럼 노출과 구분하며 자동 번역하지 않는다.
