# ADR-REVIEW-005: AI 지적의 근거·가정 검증

> ID: `ADR-REVIEW-005` · 소유: `REVIEW` · 기준: `2026-09-26`
> 읽는 때: AI 출력 허용 기준·근거 필드 변경

- 상태: `ACCEPTED`
- 기록일: `2026-09-26`
- 근거: 사용자의 남은 작업 1~3번 구현 위임, 기존 유료 평가 문맥 부족 오탐
- 대체하는 ADR: 없음 (ADR-REVIEW-004의 basis 계약을 구체화)
- 대체한 ADR: 없음

## 배경

기존 7사례 평가에서 보이지 않는 lock 반환값·트랜잭션 호출부를 가정한 지적이 반복됐다. 프롬프트 문구만 강화하는 것으로 해결되지 않았으며, 유효한 파일/줄이라는 사실도 내용의 진실성을 보장하지 못했다.

## 결정

issue에 evidence_lines(같은 파일의 제공 HEAD 줄 1~8개), trigger(1~400자), consequence(1~400자), assumptions(0~3개, 각1~400자)를 요구한다. 근거 줄은 중복이 없고 대표 line 및 변경 줄을 포함해야 한다. SUPPORTED에는 assumptions가 없어야 하며 NEEDS_CONTEXT에는 명시적 전제가 있어야 한다. NEEDS_CONTEXT+ERROR 금지는 유지한다.

없는 메서드 정의·호출 계약만을 이유로 한 지적은 허용하지 않는다는 지침을 명시한다. 단, 서버가 자연어 의미를 증명할 수는 없다. 구조 불일치는 전체 응답을 거부하며 조용한 issue 제거·심각도 강등·성공 위장을 하지 않는다. 평가에서도 지적을 점수 산정 전에 제거하지 않는다.

원문 코드를 인용하는 새 필드는 추가하지 않는다. 모델이 설명에 코드를 복제하지 않도록 지침을 제공하되 완전한 탐지 보장은 하지 않는다. 기존 반출·저장·권한·한도·재시도 제한, 버전 hash 및 신뢰 경계는 유지한다. 기존 저장 결과는 재검증/수정하지 않고 UI가 신규 필드 없음을 허용한다. DB migration은 없다.

## 대안

NEEDS_CONTEXT 전체 삭제는 유용한 조건부 지적도 잃고 점수를 왜곡한다. 키워드 차단은 한국어 표현과 언어별 용례를 일반화하지 못한다. 추가 판정 LLM 호출은 비용·오류 경로를 늘리므로 이번에 도입하지 않는다.

## 영향과 한계

출력 토큰 예산 안에서 결과 수가 줄거나 형식 실패가 늘 수 있다. 구조 검증 통과는 의미 검증이 아니다. 기존 평가 정답을 유지하고 독립 반례·위조 근거·변경 줄 없는 근거·가정 불일치와 실제 모델 출력을 검증한다. 실제 관측 결과는 구현 저장소 Report가 소유한다.
