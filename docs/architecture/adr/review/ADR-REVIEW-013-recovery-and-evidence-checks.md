# ADR-REVIEW-013: 누락 복구와 독립 근거 검사

> ID: `ADR-REVIEW-013` · 소유: `REVIEW` · 기준: `2026-09-29`

- 상태: `SUPERSEDED`
- 근거: 품질 상향 후보의 추천 순서로 보수 구현을 진행하라는 사용자 위임.
- 대체하는 ADR: [ADR-REVIEW-011](ADR-REVIEW-011-empty-recheck-and-source-view.md). 두 번째 검토와 파일 점검 위치 계약을 변경하며 사이트 내 코드 열람·반출·한도 계약은 유지한다.
- 대체한 ADR: [ADR-REVIEW-014](ADR-REVIEW-014-grounded-claims-and-repair-guards.md). 출력·원인 설명·수정안 반례 계약 보강.

## 배경

이전 평가는 잘못된 초안을 삭제한 뒤 실제 결함이 복구되지 않는 문제, 점검 대표 줄과 실제 근거 줄의 혼동, 정상 동작을 바꾸는 수정 제안을 확인했다. 호출 수와 반출 예산을 유지하면서 발견·전달·의미 검사·독립 근거를 보강한다.

## 결정

검증자는 KEEP/REVISE/DROP 외에 독립적으로 찾은 새 항목과 파일별 검토 범위를 반환할 수 있다. 새 항목도 동일한 스키마·제공 줄·변경 근거·팀 문서 인용 검증을 거친다. 원래 판단을 그대로 승격하거나 근거 위치를 임의로 고치지 않는다. 파일 점검의 대표 변경 줄은 서버가 제공된 변경 줄에서 결정하고 결함의 근거 줄과 구별한다.

첫 응답의 출력 계약이 유효하지 않으면 남은 두 번째 호출에서 안전한 원래 입력을 재검토한다. invalid 초안은 재전송하지 않는다. 추가 세 번째 호출은 없다. 실패/검토 제한을 정상 무결함과 구별하고 복구 여부를 기록한다. 기존 결과는 그대로 읽는다.

서버는 지원 가능한 제한 연산의 관찰값과 정적 보안 근거를 제공한다. 대상 소스의 실행·import·build는 금지한다. 자연어 수정안은 검증하지 않은 상태를 기본으로 표시하며, 좁은 검사에서 반례를 찾으면 명시한다. 근거 있는 결함은 수정안 검증 실패만으로 삭제하지 않는다. 독립 분석 결과는 모델이 삭제할 수 없다.

추가 문맥은 제공 파일 ID와 명시된 심볼을 통해 같은 저장소·SHA의 허용 소스를 제한 조회한다. 기존16/48KiB 코드 예산과 변경 근거를 유지하고 부족한 범위를 기록한다. 외부 의존성 취약점 정보원은 정확한 버전 메타데이터만 처리하는 별도 어댑터로 준비하며 기존 AI 반출 동의를 다른 공급자 전송 승인으로 간주하지 않는다.

조건부 추론과 Responses 구조화 출력은 비교 평가를 통과해야 기본값이 된다. 통과하지 않은 후보는 평가용으로 한정한다. 기본 Flash, 최대2회·팀하루30회·동시1개·예약/권한/취소/lease·재시도0·원문 비저장·150초를 유지한다. 버전 해시는 변경 계약을 포함한다.

## 대안

기존 삭제 전용 검증 유지, 전체 코드 무조건 확대, 높은 추론/Responses 기본 전환을 비교했다. 누락 회복 또는 지연·출력 안정성에서 충분한 근거가 없어 기본 전환하지 않는다. 독립 보안 근거와 제한 문맥은 모델 호출 수를 늘리지 않는 보완책이다.

## 영향과 한계

기존 항목만 삭제하면 원래 놓친 결함을 복구하지 못한다. 무조건 전체 문맥·고가 모델·다중 호출은 비용과 새로운 오해를 늘릴 수 있다. 파일별 관측이나 두 모델의 동의도 정확성 보증은 아니다. 구현 및 비교 결과는 [작업 계약](../../../../records/2026-09-29_quality-repair-plan.md)과 [결과 보고서](../../../../records/2026-09-29_quality-repair-report.md)가 추적한다. 496회 비교에서 Responses/조건부 높은 추론은 기본값으로 채택하지 않았다. 제한 연산 관측과 복구 계약은 구현했지만 전체 의미 품질 승인과 구별한다.
