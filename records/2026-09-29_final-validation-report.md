## 변경과 판단

기존 nested-copy 정상 코드에 반환값 변경을 요구하던 문제를 조사했다. 정상 초안도 빈 답변 재검토에서 미사용 지역 계산을 결함으로 다시 만들었다. 초안/빈 답변 지침을 ‘제공된 요구사항과 관측을 먼저 비교하고 위반이 확인되면 채택’으로 보수했다. 입력 보존 요구와 반환값 요구를 분리하고, CODE의 미사용 지역 계산을 근거 없는 결함/질문으로 승격하지 않는다. STANDARDS의 명시적인 적용 규칙은 별도로 인정한다.

같은 코드에 서로 반대인 명시적 요구사항을 넣은 대조군과 실제 alias 변경·null·await·경계 오류를 함께 검사했다. 정답/사례 이름에 맞춘 런타임 분기, blanket 삭제, 권한·입력 크기·호출 한도 완화는 없다. 출력/DB 계약 변경 없이 ADR-REVIEW-014의 채택 기준을 구체화했다. 최종 하네스는 `rh1-04a023f7105ebe1e`, 모델·추론 설정은 기존 그대로다.

팀 문서를 등록한 뒤에도 항상 등록부터 요구하던 안내 문구를 문서/적용 범위 확인 안내로 바꿨다. 실제 브라우저에서 문서 버튼이 비활성화된 원인은 Vite가 최신 파일과 다른 예전 컴파일 결과를 제공한 것이었다. 서버를 재시작한 뒤 저장소 ID 전달·문서 원문 조회가 정상 동작했다. API도 최신 하네스로 재시작했다.

## 실제 PR 세 가지 흐름

사용자가 지정한 연결 저장소의 PR #49, 고정 커밋 `562e528`에서 실행했다. 실제 조직 코드·문서 원문·리뷰 본문·화면 캡처는 공개 Git에 넣지 않았다. 읽기 검증은 지정 팀/저장소/PR과 요청자 본인 메모로 제한했다.

| 목적 | 상태 | 확정 제안/질문 | 모델 호출 | 입력/출력 토큰 | 확인한 결과 |
|---|---|---|---:|---|---|
| CODE | 완료 | 0 / 0 | 2 | 37,636 / 1,462 | 초안3건 제외,8개 변경 파일별 재검토 표시 |
| SECURITY | 완료 | 0 / 0 | 2 | 36,712 / 1,183 | 별도 보안 패턴 점검·AI 검토·빈 답변 재검토 |
| STANDARDS | 완료 | 0 / 1 | 2 | 44,492 / 1,697 | 문서 버전/섹션 인용과 원문 열람 |

모두 오류 코드 없음, 같은 최종 하네스/고정 커밋이다.12개 제공 파일은 변경8+관련4이고, 변경5개 제외·관련 문맥 부분 제공 한계를 화면에서 확인했다.0건은 전체 안전 판정이 아니다. 팀 규칙 질문은 클래스 역할 분리 여부에 대한 설계 확인이며 확정 위반으로 집계하지 않았다.

리뷰 요청→진행→완료→파일별 결과→문서 원문→사이트 내 고정 커밋 코드 보기→개인 메모 저장을 확인했다. 새 질문에 검증용임을 명시한 메모1개만 저장하고 상태는 ‘확인 전’으로 유지했다. 기존 피드백은 변경하지 않았다. GitHub에 글을 게시하지 않았다.

## 실제 챱챱 문서 RAG

첨부한 원본을 팀 비공개 문서 ‘챱챱 코드 컨벤션’ 버전1로 등록했다. 원문14,387바이트/19섹션이며 BOM/개행을 포함해 원본과 저장 본문 일치를 확인했다. 별도 패키지 구조 문서를 발명하지 않았고, 첨부 문서에 포함된 백엔드 구조/역할 섹션을 그대로 사용했다. include는 전체 경로, optional 문서, 자동 검사 규칙은 빈 목록이다. 규칙을 코드 설정으로 임의 변환하지 않았다.

요청 시 활성 버전1 고정, 경로+BM25 검색으로19개 중8개 선택/11개 제외, fallback 없음. 선택 섹션에 백엔드 구조·역할, 기본 작성, 이름, MSA/보안, Kafka 책임이 포함됐다. 실제 질문은 기본 작성 규칙을 인용했고 버튼으로 같은 버전 섹션 원문을 열 수 있었다.12KiB 한도 안의 선택 검색이며 문서 전체 검토가 아니다. 경로 `**`이므로 Python 섹션 등 관련성이 낮은 내용도 들어갔다. 향후 문서를 기술/경로별로 분리하고 핵심 규칙의 필수 여부를 정하면 검색 낭비를 줄일 수 있다. 임베딩/리랭커 추가는 이번 범위에서 하지 않았다.

## 남은 범위
