# 배포 전 완성도 Gate와 반복 검증 기록

## 작업 계약

- 요청: 프론트·백엔드 전체를 배포 전까지 자체 점검하고, 실패한 Gate를 수정 후 같은 기준으로 재검증한다.
- 규모 L. 코드 저장소 dev, 아키텍처 main. 문서/리포트는 아키텍처에만 저장한다. 실제 배포, AWS 자원 생성, 운영 데이터 변경, 대상 PR 변경은 하지 않는다.
- 기준: CORE, PACKAGE-RULES, CODE-CONVENTIONS, REVIEW, SECURITY-PRIVACY, TESTING, DEPLOYMENT, ADR-REVIEW-012~014. GateGuard, verification-loop, browser-qa 적용.
- 유료 평가: 기존 승인 캠페인 5,000회 중 시작 시 2,948회 사용. 필요할 때 공통 원장에 먼저 예약하며 기존 결과를 덮어쓰지 않는다. 조직 코드와 문서, 인증값, 화면 원본은 공개 Git에 올리지 않는다.
- PASS에는 명령/테스트/관찰 증거가 필요하다. 실패는 원인·수정·동일 검증 결과를 남긴다. 운영 정보가 없어 검증하지 못한 항목은 BLOCKED로 남기며 전체 배포 PASS로 바꾸지 않는다.

## 수정 전 발견과 반복 기록

1. F1: 파일별 재검토에서 코드 보기를 연 뒤 리뷰 이력을 변경해도 이전 파일 선택이 유지된다. 새 리뷰의 파일 ID에 이전 경로가 표시될 수 있다. 회귀 테스트로 재현 후 선택을 초기화한다.
2. F2: 같은 문서/섹션의 버전이 바뀌어도 열린 인용 본문이 남고 이전 비동기 응답이 새 버전에 붙을 수 있다. 요청 식별자와 인용 키로 응답/상태를 격리한다.
3. F2: 문서 본문을 편집한 뒤 이전 섹션 번호에 연결된 규칙이 다른 의미의 섹션을 참조할 수 있다. 편집/미리보기/규칙 재연결 상태를 명확히 분리한다.
4. S2/F2: Markdown 코드 블록을 불리언으로 처리해 4개 백틱 내부의 3개 백틱 또는 다른 구분자가 블록을 닫고 코드 안의 제목을 문서 제목으로 오인할 수 있다. 구분자의 종류와 길이를 추적한다.

### AI 최소 기준과 한계

최종 H4는 **86평가, 고유 78사례, 형식 86/86, 정상 오탐 0, 기존 대표 줄 누락 지표 3, 근거 줄 누락 지표 0**이다. 경로 경계/중첩 복사 4사례×3반복은 직접 의미 검수했다. 경로 수정안이 루트 자신과 하위 경로를 유지하고 형제 접두사 경로를 거부하는지 확인했다. 3개 대표 줄 불일치는 복사 2줄 대신 실제 쓰기 3줄을 가리키며 근거에 2~4줄을 포함했다. 기존 실패 집계를 지우거나 모든 응답을 의미 정답으로 바꾸지 않았다.

근거: [최종 지표](quality-evaluations/predeployment-hardening-20260929/H4-focused-summary.json), [12개 응답 의미 검수](quality-evaluations/predeployment-hardening-20260929/H4-semantic-review.json). 나머지 74응답의 위치/형식 통과는 전체 원인 설명·수정안 정답을 보장하지 않는다. 반복 사용한 합성군은 독립 holdout이 아니다. 실제 대형 PR의 전 경로 누락 0·보안 안전성을 주장하지 않으며 제품의 범위/미검증 안내를 유지한다. 기존 실제 PR 결과는 재작성하지 않았다.

이번 **516회** 호출(합성 데이터만), 승인 캠페인 **3,464/5,000회**, 잔여 **1,536회**. 과거 호출 포함 **5,027/6,563회**. 팀30회/일·요청당2회·Flash 설정은 변경하지 않았다. 공통 usage.json이 원장이며 H1–H4 결과/실패를 보존했다.

### 기능/UI 증거

- 기존 Vue 컴포넌트와 파란색 토큰을 유지했다. 사용자 과업은 올바른 리뷰의 코드를 확인하고, 편집한 문서의 새 근거에 규칙을 연결하는 것이다. 새로운 화면/컴포넌트 체계를 만들지 않았다.
- 실제 로그아웃→보호 PR 경로 차단→GitHub 로그인→원래 PR 복귀 확인. 실제 파일별 코드 보기→리뷰 이력 변경 시 열린 코드 영역 제거 확인. 기존 실패 리뷰의 오류/범위 안내 확인.
- 문서 편집은 합성 미저장 초안만 사용했다. 본문 수정 후 규칙 값 보존·섹션 초기화·저장 비활성, 미리보기/재연결 후 활성 확인. 저장하지 않고 닫았으며 실제 팀 문서 버전은 바꾸지 않았다.
- 로그인·메인·팀·리뷰·문서 편집을 320/375/414/768/1280px에서 확인. [너비 수치](backend/reports/2026-09-29_hardening-ui-widths.json)에 가로 넘침 없음. 리뷰/편집의 주요 요소 경계, 데스크톱/모바일 화면, 탭 Home·Enter·Tab 포커스를 확인했다. 완전한 스크린리더 접근성 인증을 뜻하지 않는다.
- 조직 코드/문서가 보이는 원본 스크린샷과 API 본문은 공개 Git에 저장하지 않았다. 검증용 모바일 화면은 로컬 audit-artifacts/hardening-20260929/mobile-rules.png에 보관했다.
