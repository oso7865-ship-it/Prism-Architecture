# ADR-DEPLOY-009: 공개 GHCR 이미지와 EC2 자동 배포

> ID: `ADR-DEPLOY-009` · 소유: `DEPLOY` · 기준: `2026-09-30`
> 읽는 때: 이미지 공개 범위·배포 인증·프론트 산출물 전송을 변경할 때

- 상태: `ACCEPTED`
- 기록일: `2026-09-30`
- 근거: 사용자가 포트폴리오 목적을 설명하고 “공개 이미지로 진행 — 포트폴리오용”을 선택했다.
- 대체하는 ADR: [ADR-DEPLOY-008](ADR-DEPLOY-008-frontend-on-ec2.md). 그 문서가 유지하던 DEPLOY-006의 private GHCR 부분만 공개로 변경하고 프론트 산출물 전송을 구체화한다.
- 대체한 ADR: 없음.

## 배경

사용자는 소스 저장소를 포트폴리오로 공개하고 이미지도 공개하기로 선택했다. 기존 비공개 전용 검사가 공개 이미지 게시 후 실패했고, EC2용 다운로드 토큰의 추가 관리가 불필요해졌다.

## 결정

프론트와 백엔드는 같은 EC2/Caddy에서 제공하며 기존 두 도메인·동일 출처·TLS·쿠키·CSRF·RDS 계약을 유지한다. Actions main CI를 통과한 이미지를 공개 GHCR에 게시한다. 게시에는 Actions의 단기 GITHUB_TOKEN을 쓰고, EC2 다운로드에는 인증 토큰을 쓰지 않는다. 소스 공개와 별개로 이미지 공개를 명시적으로 선택한 결정이다.

백엔드는 ghcr.io/oso7865-ship-it/prism-backend, 프론트는 ghcr.io/oso7865-ship-it/prism-frontend를 사용한다. 업로드 후 익명으로 정확한 digest의 manifest를 받아 해시를 검증하고 실패하면 배포하지 않는다. 운영 환경값·인증키·DB 데이터는 이미지에 넣지 않는다. 백엔드의 Docker build context 허용 목록과 프론트 dist 전용 context로 범위를 제한한다.

프론트는 빌드한 정적 파일만 scratch OCI 이미지의 /site에 담는다. EC2 도구는 컨테이너를 실행하지 않고 파일을 추출하며, 경로 이탈·링크·숨김/비허용 파일·용량 초과를 거부한다. source/revision/digest를 확인하고 버전 디렉터리에 설치한 뒤 current 링크를 원자적으로 바꾼다. 공개 자원 해시·SPA·API 준비 상태가 실패하면 이전 링크로 복원하고 배포는 실패로 기록한다.

저장소별 production 환경·OIDC 역할·고정 SSM 문서·지정 EC2·배포 잠금/순서 검사, 백엔드 migration 전 백업 복원·preflight·실제 readiness·제한된 rollback을 유지한다. 역할은 main 전용 production 환경의 실제 OIDC subject로 제한한다. Caddy 및 root 관리 배포 도구의 변경은 별도 설치 단계다.

## 대안

비공개 이미지는 실행 산출물 다운로드를 제한하지만 공개 소스의 열람을 막지는 않는다. 이번 포트폴리오 용도에서는 토큰 만료·배포 실패 관리를 줄이기 위해 공개를 선택했다. 공개된 이미지는 누구나 받을 수 있고 GitHub에서 다시 비공개로 바꿀 수 없다. 공개 승인 전의 비공개 전환 커밋과 시도는 이력이며 현재 정책이 아니다.

## 영향과 한계

공개 이미지에는 실행 코드가 포함된다. 서버의 운영 설정과 DB는 별도 비공개 자원이며 이 결정으로 공개되지 않는다. 단일 EC2의 장애 영역과 백업·인증·권한 검증 책임도 유지한다.
