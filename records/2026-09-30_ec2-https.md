## 범위와 근거

사용자가 EC2 HTTPS 설정을 위임하고 80/443 인바운드가 열려 있다고 확인했다. 적용 범위는 호스트 Caddy와 API 인증서다. 읽은 소유 문서는 CORE, DEPLOYMENT, OPEN-ITEMS, ADR-GUIDE, ADR-DEPLOY-006이며 terminal-ops 절차를 적용했다. RDS·앱 비밀·GitHub 설정·앱 배포 활성화는 변경하지 않았다. 새 기술 선택은 ADR-DEPLOY-007에 기록했다.

## 적용한 설정과 운영

```caddyfile
{
    log default {
        format filter {
            wrap json
            fields {
                request delete
            }
        }
    }
}

api-prismquest.p-e.kr {
    reverse_proxy 127.0.0.1:8000
}
```

Caddy fmt 적용 후 서버 파일 SHA256은 `df21f809049f3884a989d7ef3c6e2360843dc6a2de121858acaa6a798510da06`이다. 인증서는 `/var/lib/caddy/.local/share/caddy`에 영속 보관된다. 이 디렉터리를 이미지 교체 때 삭제하지 않는다. 정상 설정 변경은 `sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile` 성공 후 `sudo systemctl reload caddy`로 적용한다. 인증서 수동 교체나 별도 Certbot 갱신 작업은 필요하지 않다.

초기 패키지 설정과 로그 필터 전 설정은 `/var/lib/prism-bootstrap/caddy/`에 보존했다. 추후 설정 오류는 검증된 직전 설정을 복원·validate·reload한다. 이번 설정은 HTTPS 인프라만 활성화했으며 `/etc/prism/deploy.json`의 enabled=false는 유지했다. 다음 작업은 운영 앱 키·배포 권한·이미지·백업 복원 준비 후 실제 백엔드 배포와 ready=200 검증이다. 실제 부팅 테스트·만료 전 갱신 실행·프론트 도메인·OAuth·Webhook 검증은 이번 결과에 포함하지 않는다.

## 실행 기록

서버 cwd는 SSH 기본 ubuntu 홈, 설치는 sudo bash에서 수행했다. 공식 패키지 설치와 검증된 설정 반영은 사용자 위임 범위의 비파괴 환경 변경이다. 임의 외부 설치 스크립트를 실행하지 않았으며 서버 파일 삭제·DB 변경·재부팅은 없었다. apt가 Caddy 설치 전 서명 검증 도구 의존성을 갱신했다. 설치/validate/reload/외부 TLS 검증의 종료 코드는 0이다. 인프라 Gate는 PASS, 앱 준비 Gate는 미완료다. 문서는 아키텍처 저장소에만 추가했고 이번 HTTPS 변경은 아직 Git 커밋·푸시하지 않았다.
