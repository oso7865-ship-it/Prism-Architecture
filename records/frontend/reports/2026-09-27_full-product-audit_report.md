## 1. 결론

로그인, PR 동기화, 정적 분석 등 핵심 기능은 작동한다. 파란 계열의 일관성, 목록/상세 분리, 모바일 로그인 우선 배치, 비색상 상태 표시는 유지할 장점이다.

**다음 수정 묶음은 로그인 복귀 → 동기화 복원 → 팀 멤버 식별 → 리뷰 탐색 → 오류 메시지 범위 정리 순서가 적절하다.** 현재는 배포 준비 전체 PASS로 판정하지 않는다. 감사 산출물 작성 완료와 제품 미해결 결함을 구분한다.

## 5. 발견 사항

### F01 · P1 · 로그인 과정에서 원래 작업 위치와 초대 정보가 사라짐

- **재현:** 로그아웃 → 기존 team/repo/pr query가 있는 PR URL 진입 → `/login?next=/app/repositories`로 이동 → GitHub 로그인 → `/app?team=…` 홈에 착지.
- **원인:** [router.ts](../src/app/router.ts) 24행이 `to.path`만 보존한다. [LoginView.vue](../src/app/LoginView.vue) 35행은 고정 로그인 URL을 쓰며 `next`를 소비하지 않는다. backend `app/domain/auth/router.py` 71행도 성공 시 `/`로 보낸다.
- **영향:** PR 링크 공유/세션 만료 후 재탐색 필요. 초대 링크의 `#invite`도 같은 guard에서 소실되는 것은 소스상 확인이며, 실제 다른 사용자 초대 수락은 재현하지 않았다. 온보딩 때문에 우선순위를 높였다.
- **제안:** 허용된 내부 복귀 경로와 pending invite를 OAuth 왕복 동안 보존하고 로그인 성공 시 복원한다. 외부 URL 거부 및 토큰 노출 방지도 함께 검증한다.
- **완료 기준:** 로그아웃 상태 PR 링크와 초대 링크를 각각 열어 로그인 후 원래 PR/초대 수락 화면으로 복귀. 취소/만료 시 재시도 정보 유지.

### F02 · P2 · PR 동기화 상태와 다음 페이지 정보가 복원되지 않음

- **재현:** PR 동기화 → 상태 확인 → 완료30개 → reload. 마지막 동기화 시각과 PR 목록은 남지만 상태 확인 제어는 사라진다.
- **원인:** [WorkspacePanel.vue](../src/features/workspace/WorkspacePanel.vue) 38/101–103행에서 `sync`는 메모리 상태이며 저장소를 열 때 null로 초기화한다. 183행의 이전 PR 버튼도 `sync.next_cursor`에만 의존한다. backend PR API는 run ID 개별 조회만 노출한다.
- **영향:** 진행 중 작업을 나갔다 돌아와 추적할 수 없다. 이전 PR 가져오기 역시 새 동기화 이후에만 다시 접근 가능하다. 새로고침 후 상태 제어 유실은 실화면, 다음 페이지 연결 원인은 소스로 확인했다.
- **제안:** 저장소별 최신/진행 중 sync 조회 및 복원, 완료까지 상태 갱신, 서버가 보존한 페이지 커서로 이어 가져오기.
- **완료 기준:** 대기·실행·완료 상태마다 reload/저장소 전환 후 같은 작업과 다음 커서를 회복하고 중복 실행을 만들지 않음.

### F03 · P2 · 다른 팀 멤버를 이름으로 구분할 수 없음

- **근거:** [WorkspacePanel.vue](../src/features/workspace/WorkspacePanel.vue) 191행은 다른 사용자를 모두 `팀 멤버` + 내부 UUID로 표시한다. backend `app/domain/workspace/schema/response.py` 14–17행 응답도 user_id/role만 포함한다.
- **영향:** 사용자가 늘면 제거·관리자 변경·소유권 이전 대상자를 확인하기 어렵다.
- **제안:** GitHub login/display name/avatar를 조회 계약에 포함하고, 권한 변경 확인에도 `@login`을 명시한다.
- **검증 한계/완료 기준:** 실제 팀은 1명이므로 다인원 화면 재현은 미수행. 두 명 이상 테스트 계정에서 표시와 변경 대상 일치를 검증해야 한다.

### F04 · P2 · AI 리뷰와 PR 활동이 긴 정적 결과 아래 묻힘

- **근거:** 1440×1000 표본, 발견11건일 때 정적 분석 제목 y831, AI 제목 y4638, 총 높이5480px. 기존 AI 결과를 표시하면 페이지는 더 길어진다. [AnalysisPanel.vue](../src/features/analysis/AnalysisPanel.vue) 133행의 AI 영역이 전체 정적 결과 아래에 있다.
- **영향:** AI 기능 발견과 정적/AI 결과 비교에 반복 스크롤이 필요하다. 모바일의 긴 경로와 카드 중첩이 이를 더 키운다.
- **제안:** 상세 상단에 `개요 / 정적 분석 / AI 리뷰 / 활동` 탐색 또는 즉시 이동 링크를 두고, 결과 요약과 목록 확장을 분리한다. 긴 경로는 파일명 중심으로 줄이고 전체 경로를 펼쳐 볼 수 있게 한다.
- **완료 기준:** 기본 결과를 숨겨야만 AI에 빨리 도달하는 상황이 없어지고, 키보드·모바일에서도 한 번의 명확한 행동으로 원하는 영역에 접근.

### F05 · P2 · 이전 페이지의 오류가 새 페이지에도 표시됨

- **재현:** 팀 설정 → 사용자명 `../invalid` → 계정 확인 → 오류 표시 → 저장소와 PR 이동. 저장소 화면 상단에 계속 `GitHub 사용자명을 입력하세요`가 남음(05–06).
- **원인:** [WorkspacePanel.vue](../src/features/workspace/WorkspacePanel.vue) 33–34/54/148행. 같은 컴포넌트와 message/failed를 재사용하며 route 변경 시에는 포커스만 옮긴다.
- **제안:** 오류를 요청·폼에 귀속시키고 관련 페이지를 벗어나면 해제. 입력 오류를 해당 필드와 연결한다.
- **완료 기준:** 팀 오류가 저장소/홈에 나타나지 않고 원래 폼의 복구 정보는 필요한 동안 유지.

### F06–F07 · P3 · 키보드 메뉴 닫기와 좁은 화면 밀도

- **F06 실관측:** 계정 메뉴 summary를 Enter로 펼친 뒤 Escape를 눌러도 `details.open=true`, 로그아웃 버튼 노출 유지. [HomeView.vue](../src/app/HomeView.vue) 32행에 닫기 핸들러 없음. Escape·바깥 클릭 닫기와 트리거 포커스 복귀를 권장한다. 모달 포커스 트랩이 필요한 화면이라고 단정하지 않는다.
- **F07 실관측:** 320px에서 `작업 공간 홈`, `저장소와 PR`이 두 줄이고 상단 팀/저장소 선택이 많은 높이를 차지한다(11). 저장소 경로도 select에서 잘린다. 가로 넘침이나 기능 차단은 없지만 짧은 메뉴명과 선택 저장소의 읽기 쉬운 요약을 권장한다.
- **글자 크기:** 일부 중요 메타/도움말은 실제 9–11px이다. 본문·보조 정보 크기 재정리를 권장하되 전체 색 대비/WCAG 적합 판정은 수행하지 않았다.

## 6. 미해결과 재점검 순서

1. F01–F03 기능·식별 계약을 설계한 후 수정. 컴포넌트를 마운트하는 회귀 테스트를 추가한다. 현재 router 테스트는 Vue 화면을 mock하므로 이런 동선 결함을 놓칠 수 있다.
2. F04–F07 UI 흐름을 정리하고 같은 5개 너비·키보드·오류 시나리오를 재검증한다.
3. 운영 스크립트 E501 5건 수정 및 CI 검사 범위 포함 여부 결정. 현재 CI에는 app/tests/migrations만 포함된다.
4. Windows native 예외가 없는 격리 환경에서 확인. 앱 기능 테스트 PASS만으로 로컬 환경 문제를 해제하지 않는다.
5. 실제 다른 사용자·조직 권한·공개 HTTPS OAuth/Webhook, 새 AI 모델 품질은 별도 검증. 기존 AI 내용 품질 과제는 이번 유료 실행 0회로 재평가하지 않았다.
