# 공통 고정 기준

> ID: `CORE` · 소유: `architecture` · 기준: `v0.1.0 / 2026-09-25`
> 읽는 때: 모든 작업 시작

## 제품과 범위

**프로젝트명: PRism(프리즘)**. 다른 사용자도 가입하고 저장소를 연결할 수 있는 구조로 개발하며, 초기에는 본인 GitHub Organization과 개인 프로젝트에서 사용한다. 즉시 공개 출시는 하지 않는다.

팀이 GitHub PR을 조회하고, 정적 규칙으로 발견한 항목과 선택적 AI 설명을 확인하는 플랫폼이다. 코드의 완전한 안전성·정확성·기업 도입 적합성을 인증하는 제품이 아니다.

사용자 선택: Python 백엔드, LangChain 활용, AWS EC2 백엔드 배포, 지원 분석 언어 **Java / JavaScript / TypeScript / Python**. Go는 제외한다. 프론트는 기존 논의에 따라 Vue/Vercel을 설계 기본값으로 둔다.

## 바뀌면 안 되는 경계

- `domain`은 업무 개념의 소유자다. 여러 곳에서 사용해도 WorkspaceRole·Finding·PR 정책은 소유 도메인에 남는다. `shared`는 도메인 중립 기술 공통 코드다.
- Router는 HTTP, Service/UseCase는 업무 흐름, Repository는 DB 접근, Request/Response는 HTTP 스키마다. 다른 도메인의 ORM·Repository를 직접 사용하지 않는다.
- 로그인 사용자 인증, Workspace 권한, GitHub 설치 권한은 별개다. 조회·분석·AI 요청·백그라운드 실행 모두 테넌트 경계를 검사한다.
- 실제 분석은 HTTP 응답과 분리한다. 접수 DB 트랜잭션이 커밋된 뒤 `202`를 응답한다. Job 재시도는 중복 실행될 수 있으므로 저장을 멱등하게 만든다.
- 분석 대상 소스·설정·PR 본문은 신뢰하지 않는다. 코드를 실행하거나 의존성을 설치하지 않는다. 원문·Diff·비밀키를 DB/로그/Job에 보존하지 않는다.
- 분석 결과는 고정한 commit SHA·규칙/설정/분석기 버전에 귀속한다. 새 commit 결과가 과거 결과를 덮어쓰지 않는다.
- Tree-sitter 구문 분석을 타입 추론·전체 프로그램 증명으로 취급하지 않는다. 모르는 것은 `NOT_EVALUATED`, 범위 누락은 `PARTIAL`로 드러낸다.
- 정적 Finding과 AI 설명은 별개다. AI는 원래 Finding/Severity를 수정하거나 코드를 자동 적용하지 않는다. AI 실패가 정적 분석 성공을 실패로 바꾸지 않는다.

## MVP 경계

기존 PR은 최근 30개 메타데이터를 우선 동기화하고 사용자가 고른 PR만 분석한다. 새 PR/추가 commit은 허용된 Webhook 이벤트에 따라 자동 접수한다. 과거 전체 이력의 완전한 재생, 자동 PR 댓글/머지, 저장소 빌드·테스트, 전역 타입 분석, RAG, Kafka/Redis/MSA는 MVP에 넣지 않는다.

## 읽기 원칙

세부 상태·수치·API는 각 소유 문서가 기준이다. 이 문서는 그 내용을 중복 정의하지 않는다. 문서의 `설계 기본값`은 구현·측정으로 검증할 대상이며 사용자 승인이나 검증 완료 사실로 표현하지 않는다.
