# 리뷰 품질과 작업 흐름 개선

- 규모: XL. backend dev / frontend dev / architecture main.
- 근거: 사용자의 세 묶음 구현 승인과 블루스크린 후 계속 진행 요청.
- 목표: 근거 없는 추측을 결함과 분리하고, 제한된 코드 문맥과 처리 기록으로 리뷰 판단을 돕는다.
- 범위: review 입력·출력·피드백 API, 최신 PR 동기화 조회, PR 상세 탭, 로그인 목적지 복원, 멤버 식별과 화면 상태.
- 제외: 유료 모델 평가 재실행, GitHub 게시/자동 수정, 배포, 커밋·push.
- 적용: terminal-ops, ui-ux-design, vue-ui-polish. Security/DB/UI/문서 Gate.
- 승인 해석: 현재 구현 위임은 필요한 추가 스키마와 되돌릴 수 있는 로컬 실행을 포함한다. 데이터 삭제/권한 확대는 하지 않는다.

## 설계

1. SUPPORTED와 NEEDS_CONTEXT를 검증한 뒤 각각 발견 사항과 검토 질문에 보존한다. 분류 이동은 결과에 명시하고 평가에서 누락시키지 않는다. 과거 결과는 변경하지 않는다.
2. 고정 HEAD의 변경 파일에서 근처 코드를 읽고, 같은 커밋의 제한된 관련 파일을 보조 문맥으로 선택한다. 최대 8개 변경 파일 + 2개 관련 파일, 총 입력 24KiB. 관련 파일은 변경 결함의 대표 위치가 될 수 없다. 문맥 수집 실패·제한을 표시한다. 저장되는 것은 위치·수량·사유이며 원문은 저장하지 않는다.
3. 근거 코드 조회는 로그인·팀·저장소 연결을 요청 전후 검증한다. 서버가 저장 결과의 경로와 SHA를 결정하고 범위를 제한한다. 비밀 의심·바이너리·비정상 경로는 거부한다. no-store 응답.
4. 개인 처리 기록은 review_feedback에 저장한다. 논리 참조만 사용하고 run/user/issue_key 유일성, 허용 상태, UTC 시각을 보장한다. 메모는 500자 이하, 비밀 의심 문자열 거부. 다음 리뷰의 같은 작성자 기록은 제한된 참고 정보이며 모델 지침이 아니다. 자동으로 지적을 숨기지 않는다.
5. PR 상세는 개요/정적 분석/AI 리뷰/활동으로 분리한다. 카드에는 요점·위치·처리 상태를 먼저 표시하고 상세를 펼친다. 이전 회차 비교는 신규/반복/이번에 미검출이며 자동 해결 판정하지 않는다.
6. 로그인 목적지는 내부 경로만 허용하고 탭 단위 15분 복원 정보를 사용한다. 접근 토큰은 저장하지 않는다. 초대 fragment는 OAuth 왕복에 필요한 동안만 유지하고 복원 후 삭제한다. 동기화는 서버의 현재 연결 세대 최신 기록으로 복원한다.

## 변경 안전성·검증

- DB: 새 피드백 테이블만 추가한다. 기존 테이블/결과 수정 없음. 로컬 적용 전 pg_dump 백업; 롤백은 새 테이블만 제거(신규 피드백 소실)하므로 필요 시 먼저 내보낸다. 격리 prism_test에서 upgrade/downgrade 검증 후 로컬 upgrade.
- Security 설계 PASS: 인증·팀 범위·연결 세대 재검증, 입력 제한, 고정 GitHub 호스트·SHA, 외부 응답 크기/시간 제한, 원문 비저장, no-store, 메모 지침 불신. 구현 테스트로 재검증한다.
