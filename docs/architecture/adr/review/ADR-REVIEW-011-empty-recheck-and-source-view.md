# ADR-REVIEW-011: 빈 리뷰 재검토와 사이트 내 코드 열람

> ID: `ADR-REVIEW-011` · 소유: `REVIEW` · 기준: `2026-09-28`

- 상태: `ACCEPTED`
- 근거: 사용자의 빈 결과 버그 수정 및 사이트 내 코드 열람 요청.
- 대체하는 ADR: [ADR-REVIEW-010](ADR-REVIEW-010-evidence-first-verified-review.md). 빈 초안 처리와 코드 열람 범위를 변경한다.
- 대체한 ADR: 없음.

## 배경

최근 실제 결과는 빈 초안 뒤 재검토 없이 완료됐다. UI나 verifier에서 항목이 사라진 증거는 없으며 과거의 다른 답변만으로 실제 결함 누락을 확정할 수 없다. 기존 코드는 지적이 있어야 주변 코드에 접근할 수 있고 카드 안에 숨겨져 있어 0건 결과에서는 검토 범위를 직접 살펴보기 어렵다.

## 결정

첫 초안에 제안·질문이 있으면 기존 KEEP/REVISE/DROP 검증을 유지한다. 둘 다 없으면 같은 안전한 코드 입력을 별도 호출로 다시 검토한다. 두 번째 응답에는 기존 summary/issues/limitations와 file_checks를 요구한다. 모든 변경 파일을 정확히 한 번씩 포함하며 file_id, 실제 제공된 변경 줄, FINDING/NO_FINDING/LIMITED, 짧은 한국어 관측 결과를 담는다. 이는 숨은 추론이나 전체 파일 검증의 증거가 아니다.

누락·중복 파일, 허위 위치, 비밀 의심 내용, 항목과 결과의 불일치는 거부한다. 새 제안은 기존 출력/근거 검증을 통과해야 한다. 형식/제공 범위 검증은 의미적 정확성을 보장하지 않는다. 새 항목에는 별도 verifier를 거치지 않았으므로 CHECKED를 부여하지 않고 EMPTY_RECHECKED와 file_checks로 구분한다. 정상적인 0건은 허용하며 문맥 부족을 명시한다. 두 번째 호출 실패는 FAILED로 끝내고 빈 초안을 성공으로 반환하지 않는다. 기존 결과는 수정하지 않으며 과거 빈 답변은 파일별 재검토 미수행으로 표시한다.

GET /reviews/{rid}/source-files/{file_id}?line=N은 저장된 coverage.files의 서버 매핑으로만 파일을 결정한다. 임의 경로나 SHA를 받지 않는다. 기존 /source/{key}도 유지하고 선택적 line을 지원한다. 줄은1..200000, 응답은80줄 페이지·한 줄300자 및 total_lines다. 고정 HEAD의 실제 파일 취득은200KB·20초, regular blob·UTF-8·비밀정보 필터, 외부 요청 전후 권한/연결 세대 검사, no-store를 유지한다. AI에 제공된 코드보다 넓은 파일 범위를 열람할 수 있음을 화면에 구분한다. 소스는 DB/로그/브라우저 저장소에 보존하지 않고 닫기·리뷰 이동 시 메모리에서 폐기한다.

## 영향과 한계

V4 16KiB/파일·48KiB 전체, 변경8·관련4, 리랭커OFF, 동의/팀하루30회·동시1개·최대2회 호출·회당60초/2000토큰·전체150초·재시도0, 호출 전 예약·권한·연결·취소·lease 검사, 토큰 합산, 원문 비저장, 과거 결과 불변을 유지한다. 빈 답변도 두 번 호출하므로 실제 평균 비용과 지연은 늘어난다. 동일 모델의 공통 누락과 오탐은 여전히 가능하며 지적 수를 강제하지 않는다. 하네스 변경은 버전 해시에 반영한다.

## 대안

항목 수를 강제하면 허위 지적을 만들고, 안내 문구만 바꾸면 빈 초안 즉시 종료가 남는다. 세 번째 verifier 추가는 기존 비용 상한을 바꾸므로 채택하지 않는다. 제품 코드를 새 평가 대상으로 자동 전송하지 않는다. 합성 결함/정상 사례, 응답 계약, 호출·권한 경계, 소스 허용 목록·페이지·취소·안전한 렌더링을 검증한다.
## 소유 문서와 검증

[Review](../../domain/review/README.md), [결과 스키마](../../contracts/schema/RESULTS.md), [보안](../../operations/SECURITY_PRIVACY.md). 실제 결과는 [작업 기록](../../../../records/2026-09-28_review-empty-source-report.md)이 소유한다.

삭제만 있어 제공된 변경 HEAD 줄이 없는 파일은 기존 제공 문맥 줄을 대표 줄로 삼고 LIMITED로만 표시한다. 삭제 코드를 읽었다고 주장하거나 근거 줄을 만들지 않는다.
