# 전체 화면 쉬운 용어 정비

## 작업 계약·설계

- 요청: 정적 분석·개요를 포함한 전체 화면을 사용자 관점으로 검수하고 수정 전후를 표로 제공한다.
- 범위: M, frontend dev. 로그인·홈·팀·저장소·변경 요청·코드 점검·AI 리뷰·개인 기록·오류·접근성 이름·브라우저 제목. 기존 미커밋 작업 보존.
- 사용자는 GitHub 계정을 연결해 변경 요청을 확인하고 점검과 AI 리뷰를 이용한다. 구현 방식을 몰라도 기능과 다음 행동을 이해할 수 있어야 한다.
- 기준 용어: 정적 분석 → 코드 점검(설명에서 규칙 기반·실행하지 않음 명시), 개요 → 한눈에 보기, PR → 변경 요청(처음에 PR 병기), 동기화 → 최신 내용 가져오기, 발견 항목 → 확인할 항목, 문맥 → 주변 코드/추가 정보, 개인 처리 기록 → 내 검토 메모.
- 상태 의미 보존: 열린 요청을 검토 중이라고 추정하지 않는다. 병합은 대상 브랜치에 코드 반영으로 설명한다. AI 제안은 확정 결함·검증 완료로 표시하지 않는다. 일일 한도는 UTC 자정을 한국시간 오전 9시로 풀어 쓴다.
- 문구 정책: 버튼은 동작, 제목은 내용, 오류는 문제와 다음 행동을 표현. 긴 설명은 기존 펼침 영역에 배치한다. 브랜드·파일명·원본 코드·사용자 제목·저장된 AI 자유 서술·규칙 번호·API enum·URL·권한 로직은 유지한다. 일괄 번역으로 원본 코드를 훼손하지 않는다.
- 구현: 기존 컴포넌트와 파란색 스타일을 사용한다. 용어를 변경한 화면의 접근 가능한 이름과 테스트 기대값도 맞춘다. 모든 실제 문구 변경을 전후·영역·이유 표로 기록한다.
- 적용: 기존 ui-ux-design/Vue polish 기준, browser-qa, verification-loop. 단순 문구·설명 변경으로 일반 위험. 계약/DB/권한/유료 호출·배포 변경 없음.
- 검증: 전체 텍스트 소유 경로 검사, 이전 기술 용어 잔존 검사, 실제 Vue 렌더/회귀, 타입·빌드, 현재 실제 PR 화면과 320/375/414/768/1280px의 길어진 탭/버튼/줄바꿈 확인. 드문 상태는 fixture, 브라우저는 기존 결과 조회만 사용.
